# Don't copy from the summary prototype: #145 Review & confirm

Prototype: `prototype-approved/summary` (`65d472d`), `/prototype/summary?variant=B`. Spec: [#145](https://github.com/AndreasUnunger/EverythingPath/issues/145). Decision: [#110 approval](https://github.com/AndreasUnunger/EverythingPath/issues/110#issuecomment-5844063536). The [blocking amendment](https://github.com/AndreasUnunger/EverythingPath/issues/145#issuecomment-5855257791) changes no scope.

- **Hardcoded phase chips, rows and week number.** `variant-b.tsx` `phaseDelta` is a constant ("Training −13", "Treasury +20 gp", "2 teams back"…). The chips stay the same even when *no exceptions, adjustments or outcomes* is ticked. The Result heading is literally "week 15", and `mock.ts` `consequences` is fixed text. Derive the chips, consequence order and check detail from real plans and provenance. §1 bullet 3, §3 ("Do not ship … hardcoded week/phase chips"), §5 live adapter.
- **Warnings only appear in the top block, never under their item.** The Fangwood Rangers recovery-cost warning never appears in amber under its Upkeep line, and the 'Team already acted' warning disappears when the exception is removed. Attach each warning to its consequence through code/subject conventions, with a phase or unassociated fallback, and keep distinct identical messages separate. §1 bullet 4, §5 warnings paragraph, SUM-09.
- **Blank reasons are saved as shared state.** `ReasonField` on adjustments and exceptions dispatches `adjust:update`/`exception:reason` on every keystroke, including an empty string. The prototype's × "Clear reason" writes `reason: ''`. Keep the last accepted value, hold an invalid or blank reason as local form state with Save/Cancel, and make × call `clear_rules_exception`, which revokes the permission and restores the underlying decision. §5 "Complete Table Adjustment and reason forms" (reason paragraph).
- **A missing adjustment reason points to Persistent.** `project()` gives adjustment-reason requirements `phase: 'persistent'`, so the Go link reads "Go to Persistent →" and the Persistent step shows "1 to decide" (see `170-focus.png`). Summary-owned forms get local focus, and the requirement names the actual adjustment. §1 bullet 1, SUM-02.
- **Number input coerces blank or malformed values to 0, and gp is whole-number only.** `onChange={… Number(e.target.value) || 0}` with `type="number"` on whole gp. Use react-hook-form + zod with `noValidate`, keep missing separate from malformed, and convert exact signed gp to copper (−0.07 gp → −7 copper). Show a field error instead of rounding or coercing. §5 money paragraph and form-validation paragraph, WEEK-14.
- **Team condition offers `blocked`.** `teamStatuses` and the kind-card hint "Active, disabled, missing or blocked" include a status that doesn't exist. Use only the existing statuses: `active`, `disabled`, `missing`. The reputation list should come from the shared domain enum, not the mock's five literals. §5 adjustment table.
- **Readiness is inferred from the requirement count.** `ready = requirements.length === 0 && !forecastPending`, and Confirm is enabled whenever `blocker` is null. `canConfirm` comes from the existing accepted review, identity and revision. Local form gating can only disable Confirm further. The prototype's *Review updated week* button does nothing and its state list is incomplete. §5 Confirmation contract, SUM-03/04/05.
- **The mock reducer mutates arrays directly, with no conflict handling.** `adjust:*` and `remote` splice the in-memory list. The real save sends the full ordered `table_adjustments` list, built against the latest accepted list, with revision/conflict recovery. An open form must not resend an array it captured earlier. §5 "Save through the existing `table_adjustments` edit…".
- **The Result uses a prototype-only subset, colour-only emphasis and a count in the label.** The rows are only rank, training, treasury, notoriety, teams, settlements and events. Show all appends a hardcoded roster string, Now shows placeholder "carried", Final differences are shown only by `text-sky-300`, and the toggle reads "Show all 13 values". Build rows from the union of source, baseline and final facts. Describe Final differences in text as well as colour. Never fabricate values when the preview is incomplete. Label the toggle **Show all values**. §1 bullet 5, §5 Result paragraph, SUM-06.
- **The layout is desktop-only.** At 390 px the page overflows horizontally by 371 px: fixed `w-64` side panel, `grid-cols-4` kind cards, four-column table (see `summary-summary-phone.png`). At 1440 the whole page scrolls. Follow §8: 2×2 kind cards and a stacked, labelled Result below tablet width; at 1280 px and wider only the middle column scrolls. Take the frame from the responsive-shell prototype (B), not this frame.
