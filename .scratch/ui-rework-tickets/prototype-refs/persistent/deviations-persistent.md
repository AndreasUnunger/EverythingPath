# Persistent (#144): don't copy these from the prototypes

Pinned: `prototype-approved/persistent` (f6d5426) and `prototype-approved/week-layout` (14659d7). Spec: [#144](https://github.com/AndreasUnunger/EverythingPath/issues/144).

- **Static numbers from the mock.** The buyoff cost is always `rank 8 × 10 × 2 = 160 gp`. Treasury is 310 or 120 gp. The Theft bonus is fixed at "Rank and focus +6 · Officers +2" and the Overseer at +3, and rank never changes. Derive cost, affordability, the next buyoff week and bonuses from the shared Resolution Preview, including rank changes and earlier spending. Show a pending value when earlier phases block the calculation. See §1 item 1, §5 "Buyoff and removed amount compatibility" and §5 "Overseer allocation" (the bonus is not hardcoded).
- **Theft mitigation only changes the header text.** In the mock, a successful Loyalty check changes the header to "keeps 90%" but the treasury does not move: the panel shows `310 → 310` in `168-focus.png`. Temporary mitigation must go through the whole-week projection so treasury and buyoff affordability update. See §5 "Checks and adjudication".
- **Low Morale's −2 is missing from the check.** A Low Morale event is carried, and its card says "Loyalty checks suffer −2", yet the Theft Loyalty breakdown leaves the −2 out. Use the real officer/event calculation, not the mock modifier list. See §5 "Checks and adjudication" and §6 ("Validate real preview values"), and `militia-rules.md` "Event: Low Morale".
- **Tapping *Ended at the table* saves an empty ending.** The card immediately stores `{kind:'end'}` with no outcome, replacing the previous decision. The spec treats an empty form as local editing: keep the last accepted decision until a nonempty outcome can be sent, and never send an empty strict acknowledgement. See §5 "Checks and adjudication" (Ended at the table paragraph) and PER-06.
- **The ended-elsewhere section is faked.** It comes from a scenario checkbox, not from preview provenance. "Change it in Activity." is plain text, not a working link, and always names Activity. Use the actual source identity and outcome (`end_persistent_event` / `event_end`) and link to the matching Activity slot or Event occurrence. If that source is undone, the saved decision must reappear. See §1 item 6, the last paragraph of §5 "Overseer allocation and changes elsewhere", and #167's source-link note.
- **Overseer support is a local reducer shortcut.** The toggle writes a hardcoded `overseerId: 'p-ilse'`, and one synchronous reducer step clears the other Persistent decisions. Nothing happens on the Event side and there is no failure path. Use Event's ordered, awaited move path across occurrence, target-check, Sabotage and nested decisions, with truthful partial-failure and conflict recovery. The unassigned line ("could add their Constitution or Charisma modifier") also names abilities, while the final copy is source-only. See §5 "Overseer allocation and changes elsewhere" and the [final approval](https://github.com/AndreasUnunger/EverythingPath/issues/109#issuecomment-5837957108).
- **Only the fields in the mock exist.** The decision type has only `die/overseerId/officerId/skill/skillBonus/outcome`. There is no custom modifier add/edit/remove, and no retained `targets`, `rolls`, `strategistCharacterId` or legacy values. Do not rebuild a decision from these fields alone. Ordinary edits must keep sibling values. See §5 "Preserve existing operations" (mitigation fields), §5 "Checks and adjudication" (custom modifiers) and WEEK-18.
- **Roll and field input rules.** `DieField` accepts negative numbers (`/^-?[0-9]*$/`) and stores a bare `die`. New edits must use Upkeep's total form (`diceTotal`, `diceCount: 1`, `sides: 20`); negative or malformed dice input is invalid, not a value. The mock's 1–20 warning is only advisory. The Rivalry skill select also shows "Diplomacy" when no skill is stored (`d.skill ?? 'diplomacy'`), which is a false selection. See §6 (first paragraph) and WEEK-14/15/16.
- **Ordering and order label.** Events are sorted only by `startedWeek`, then `order`, with no stable `eventId` tie-breaker. The within-week order appears only when `order > 0`, with a hardcoded "nd" suffix (`order+1` + "nd"), so it would print "3nd". See §1 item 2.
- **Frame and chrome from the prototypes are not the product.** The persistent prototype has its own `WeekFrame` (its Persistent step badge shows "1" instead of the step position), fake save and remote feedback, a "confirming" checkbox and a fixed full-screen portal. Neither prototype has a phone layout: at 390 px the persistent prototype's content is 760 px wide and the cards overlap (`persistent-persistent-phone.png`). The week-layout prototype's Persistent column is a rough placeholder ("Leave unattempted / Attempt mitigation / Buy off", 60 gp). It also has the page heading "Week 14 · Persistent" and a history icon, both dropped by #101's resolution. When the phase becomes ineligible it falls back to Event, whereas an ineligible direct link must normalize to Upkeep. Use the real shell and frame (responsive-shell B: 2×2 cards below 768 px). See §3, §7, §8, and the [#101 resolution](https://github.com/AndreasUnunger/EverythingPath/issues/101#issuecomment-5831260876) ("Where it overlaps with the navigation decision").
