## 1. Scope and ownership

Deliver **Militia Correction** in place at `/campaigns/<id>/militia`: browse current militia facts by section, correct one section at a time with a required reason, preserve other players' changes, and keep affected weekly choices repairable. This is shipping area **9 of 12**, after [guided Militia Setup](https://github.com/AndreasUnunger/EverythingPath/issues/138) and before Characters & officers. Authoring comes from [Write the Militia corrections implementation spec](https://github.com/AndreasUnunger/EverythingPath/issues/131) in [Rework the militia UI for ease of use](https://github.com/AndreasUnunger/EverythingPath/issues/99); this implementation issue is outside that planning map.

Own Values, Teams and their managers, Settlements, Character conditions, Items, Caches, Orders, Marketplaces, Carried benefits, and the read-only Week & carried effects view. Own section merges/conflicts, validation/warnings, correction feedback and the correction-to-week reference-repair handoff. Reuse Setup's section editors and client warning descriptors. Keep the current roster/officer editor reachable until Characters & officers supplies its replacement; the temporary fallback and section editor are mutually exclusive on this page. Character record CRUD remains reachable on Characters & officers, including before setup.

[Navigation shell](https://github.com/AndreasUnunger/EverythingPath/issues/135) owns campaign access, scoped routes, organization/account controls, maintenance banner and shared failure component. [Week frame](https://github.com/AndreasUnunger/EverythingPath/issues/137) and phase owners retain weekly editing, reference readiness, save feedback and Confirmation. This issue supplies the missing correction/recovery integration where those earlier pages need it. Later Characters & officers owns `pc | npc`, mirrored roster kind, role-dependent manager rules, Hit Dice fallback and migration of all consumers, including this page. No correction-history display/query, Historical Correction, new authority role, new weekly action, or backend contract change belongs here.

### Correction lifecycle and concurrency

1. On Correct, capture the accepted section value plus campaign/militia/current-week identity. Local raw values and a blank reason are the edit. Other devices remain free to edit.
2. Derive warnings against the newest source and current open Weekly Draft. At Save compare the latest section to the captured section using stable structural equality (the existing canonical serialization may be reused). A change to the same section, even another row, enters conflict; don't silently field-merge or overwrite it.
3. Show **Another player changed this section**, their latest values beside the player's intended values, and **Start again from their values** plus Cancel. Restart resets the baseline/fields to the newest section, clears the old reason and requires a newly reviewed correction. Do not invent an actor name: the read result has no actor. Preserve both views until the player chooses.
4. If only other sections/character records changed, merge this section onto the latest snapshot, retain all their data, run full structural/cross-reference validation and recompute warnings. Send the latest revision and explicit reason. A team manager removed from the roster meanwhile is a field/reference error, not a silently cleared assignment.
5. A server revision race is not permission to force-save. Refresh/reconcile; if the section changed show conflict, otherwise retain input/reason, rebuild the candidate and let the player retry. A week change requires restarting the correction from the new week's facts; do not apply an old-week edit to a successor automatically.
6. Save shows Saving correction… and prevents duplicates while pending. Success closes the editor and shows current accepted values with accessible feedback; other players' read views/warnings update immediately. Failure keeps input/reason. The API has no correction idempotency key: for an unknown acknowledgement, reconcile latest accepted section/revision before offering another save, never blindly replay a full snapshot or claim a reason was stored without an acknowledged save. Campaign/organization changes must not retarget a delayed write or expose old edit state.

The temporary full roster/officer editor retains its existing revision-bound save behavior, full validation and required reason; it must not run concurrently with a new section editor. Its known full-snapshot stale conflict is not silently converted into a broad merge. Use the production fallback, not prototype character controls. Later Characters & officers consumes this section-conflict/reference utility but owns safe roster-removal cascades across people/officers/managers, then removes the fallback.

### Affected choices and reachable repair

Use `draftReferenceRequirements` with the **candidate corrected snapshot as both source arguments** to detect references removed by a correction; passing the old source as `before` would incorrectly keep deleted identities available. Compare with current requirements to distinguish existing issues. Reuse the helper's handling of entities produced by staged actions and event trees. Map paths to named Activity slot positions, Upkeep decisions/transfers, operating settlement, event targets/checks/Sabotage, Persistent officer selections and Table Adjustments. Show human names when known and contextual missing-entity descriptions otherwise; never expose opaque IDs. Refresh against live choices, not a stale draft captured when Correct opened. Roster membership/condition/manager changes also use existing rules warnings/readiness where the referenced character still exists; do not falsely call removing roster membership deletion of a character record.

Show **This affects the open week** before saving, naming choices and linking to their phase/selection. Offer a reachable route to repair choices before removing the source (Cancel the correction, repair the choices, then reopen it). Warn that affected weekly choices need repair; do not imply unrelated weekly edits will save. The warning remains advisory: a structurally valid correction may still be saved, per approval. A newly staged choice racing after preflight remains possible; recompute after acceptance and on every device.

The existing server rejects **any** draft edit whose resulting **whole draft** has an orphan, with `Invalid draft entity reference`; it also blocks Confirmation. Do not loosen that check, add a multi-edit operation, silently clear choices, auto-apply a Table Adjustment or show a nonexistent successful save. The page and phase selectors must still render missing references and usable recovery controls rather than crash or disable the entire draft.

Concrete recovery using existing contracts:

- When a single existing semantic edit repairs **all** current missing references, offer the existing clear/replace/detail/phase control and check its complete candidate before sending. Keep pending/failure/accepted feedback from the weekly store. Merely clearing one slot while another orphan remains is not sufficient.
- For multiple orphans that no single edit can repair, provide **Restore missing team/settlement/item/cache** entry points in the appropriate ordinary Militia section. This is a UI path to the existing full-snapshot correction, retaining the missing identity from that campaign's current draft rather than allocating a new one. Reuse captured authoritative pre-correction facts when available; otherwise collect required facts in the normal editor, showing which choice needs them. Never fabricate old names/stats, promise historical facts after reload, allow raw-ID entry, or create a character record through this path. Standard structural validation, membership/scope checks, section conflicts and an explicit new correction reason still apply. Restoration merges only that section into the latest source and must not undo unrelated concurrent changes.
- Source restoration does not edit the draft and `canonicalLedger.save` checks carried dependencies rather than all staged choices, so separate valid section restorations can proceed even while other staged orphans remain. Restore prerequisite items before caches when required by snapshot integrity. Once all references exist, repair the staged choices normally, then make the originally intended deletion as a new reviewed correction. Do not silently save that deletion automatically.
- The existing read exposes the open draft's missing identities but no correction archive. After reload or on another member's device, recovery still starts from those identities and explicitly entered current facts; only still-available captured facts may be prefilled.
