## Outcome

Deliver the agreed militia UI rework across the live campaign flow: navigation, the weekly workspace, setup and corrections, characters and officers, finished weeks, and campaign home. Preserve the application’s existing capabilities, shared play and visual identity while making it easier to use at the table.

This is the implementation parent for the completed [Rework the militia UI for ease of use](https://github.com/AndreasUnunger/EverythingPath/issues/99) planning map. Its twelve child specs remain the authoritative implementation contracts, including acceptance criteria, prototypes, approved payload/rules changes, compatibility and validation. This parent tracks overall completion and links those contracts.

## How to run a pinned prototype

Each ticket's **Pinned area prototypes** section links a fixed commit, a route and the approved variant. The prototypes are a visual reference only and are never merged. Later amendments in the owning spec override prototype behaviour, and mock data is not a rules contract. Each area spec's **3. Prototypes** section lists screenshots and the known deviations. Most questions can be answered from those without running anything.

Every pinned commit is protected by a `prototype-approved/<name>` tag, so it keeps working even if its `prototype/*` branch is deleted.

| Prototype | Tag | Approved route |
| --- | --- | --- |
| Upkeep | `prototype-approved/upkeep` | `/prototype/upkeep?variant=A` |
| Activity | `prototype-approved/activity-slots` | `/prototype/activity-slots?variant=E` |
| Event | `prototype-approved/event` | `/prototype/event?variant=A` |
| Persistent | `prototype-approved/persistent` | `/prototype/persistent?variant=A` |
| Week layout | `prototype-approved/week-layout` | `/prototype/week-layout?variant=A` |
| Review & confirm | `prototype-approved/summary` | `/prototype/summary?variant=B` |
| Setup and corrections | `prototype-approved/setup-correction` | `/prototype/setup-correction?variant=B` (`&screen=militia` for corrections) |
| Characters & officers | `prototype-approved/characters-officers` | `/prototype/characters-officers?variant=B` |
| Finished weeks | `prototype-approved/finished-weeks` | `/prototype/finished-weeks?variant=A` |
| Campaign list/home | `prototype-approved/campaign-home` | `/prototype/campaign-home?variant=B` |
| Week shell (phone/desktop) | `prototype-approved/responsive-shell` | `/prototype/responsive-shell?variant=B`; one phase: `/prototype/responsive-shell/screen?variant=B&phase=<phase>` |
| Pages (phone/desktop) | `prototype-approved/responsive-pages` | `/prototype/responsive-pages?variant=C` (choose the page in the state panel, or `&page=<page>`) |
| Navigation | `prototype-approved/navigation` | `/prototype/navigation?variant=E` |

Run one in a throwaway worktree, never in your implementation checkout:

```bash
name=upkeep   # tag suffix from the table
git worktree add --detach "/tmp/ep-ref-$name" "prototype-approved/$name"
cd "/tmp/ep-ref-$name"
pnpm install --offline --frozen-lockfile --store-dir "$(cd <main checkout> && pnpm store path)"
#   real install: Turbopack rejects a symlinked node_modules; /tmp is a separate filesystem,
#   so without --store-dir pnpm uses an empty store there and the offline install fails.
#   If a package is missing from the store (seen for activity-slots), use --prefer-offline instead of --offline.
cp <main checkout>/.env <main checkout>/.env.local .   # without them pages fail on ConvexReactClient
pnpm exec next dev --turbopack -p <free port>   # check `ss -ltn`; avoid 3001, used by other previews
```

Open `http://localhost:<port><route>`. `/prototype/*` routes need no login. Some prototypes have a state panel for choosing scenarios; each ticket's **Focus** line says which choices show that slice. The `pnpm prototype` script in each branch has a hard-coded port, so pass `-p` directly as shown instead. When finished, stop the server and run `git worktree remove --force /tmp/ep-ref-$name`.

**Don't copy from the responsive shell/pages prototypes:**

Covers `responsive-shell` B (areas #140, #142, #143, #144, #145) and `responsive-pages` C (areas #138, #139, #141, #146, #147). The approved layouts are [#120 B](https://github.com/AndreasUnunger/EverythingPath/issues/120#issuecomment-5846493929) and [#121 C](https://github.com/AndreasUnunger/EverythingPath/issues/121#issuecomment-5846528685). Where a snapshot differs, the specs below win.

- **Review & confirm caption and ready sentence.** The shell prototype gives the last step a caption in the desktop rail and the phone step button ("11 decisions left", or "Ready to confirm"), and when nothing blocks, its footer says "The week is ready to confirm." Do not copy this. Review & confirm has no caption anywhere, and the footer or strip shows only a disabled-Confirmation reason. See #137 Frame acceptance, #145 §1 and the [#110 amendment](https://github.com/AndreasUnunger/EverythingPath/issues/110#issuecomment-5844063536).
- **Locked Persistent changes the step count.** With "no carried events" ticked, the prototype's `usePrevNext` drops the locked step, so the phone button reads "Step N of 4". Keep "Step N of 5" with all five positions shown. Persistent stays visible and disabled as **No carried events**; only previous/next skip it (#137 Frame acceptance and Responsive acceptance).
- **Reference panel content and mock values.** The prototype panel is always open and has no Officers or History tabs. It also lacks Open militia, All finished weeks and the treasury minimum, and on Summary it hides This phase. Its values come from five separate phase mocks that don't agree (Summary warns about "Fangwood Rangers", who doesn't appear in Upkeep; treasury goes 1240 → 1745). Build the panel to #137 "Reference panel and feedback acceptance": it is closable with a remembered preference, has the tabs and links, and takes Now and After from one Resolution Preview. The phone sheet must also reach the tabs and links (#137 Responsive).
- **Inert navigation.** Both prototypes draw the section tabs, bottom-bar items, campaign switcher and organization switcher as spans or mock buttons. The bottom bar shows the short labels "Finished" and "Characters". Ship real links scoped to the campaign, with full accessible names. The More sheet must close on selection and return focus (#135 Shell behavior acceptance, Phone; #135 §3 "functional links instead of mock spans").
- **Save, remote and setup-notes chrome.** The shell prototype has no Setup notes button, and its save and remote notes are STATE-panel toggles. The pages stand-in shows a "Saved" check and a Setup-notes icon on Militia, Characters and Finished weeks. Status and Setup notes belong only to the Week frame, with notes shown only when notes exist, using #137's exact status strings. Phone icons need accessible text (#135: "Only the week mounts week-specific status/reference controls"; #137 feedback acceptance, WEEK-06 and WEEK-09).
- **The pages prototype's stand-in shell.** On phone it scrolls the section tabs sideways under the top bar. Before setup it collapses to two tabs ("Set up militia · Characters"). It also scrolls inside a fixed container that leaves a 48px gap for the variant switcher. Instead, host the pages in the real #120 B shell (bottom tabs plus More, reason bar above the tabs) and keep every section visible before setup. Pages scroll normally, without the Week three-column no-page-scroll rule. See #135 §2 precedence, #141 §3 ("Integrate the actual shell, not its stand-in"), #146 and #147 acceptance.
- **Finished weeks Result table on phone.** At 390px the prototype keeps the four-column Result table (Value / At confirmation / Rules baseline / Final). The Final column overflows and is clipped (see `history-pages-phone.png`). Use stacked, labelled Now / Rules Baseline / Final values with no horizontal overflow (#146 acceptance; #145 acceptance and the #120 Summary phone fix apply the same rule to Review & confirm).
- **Campaign home mock content.** The home pane shows the next-up line "Continues at activity.", a hardcoded "12 Pharast 4717" date and recent weeks from fixtures. Omit next up. Continue opens the first not-ready eligible phase using Week-frame readiness. Use the existing fantasy-calendar conversion, and take the latest three weeks only from the owned Finished weeks listing (#147 §1, §3 approved differences and acceptance).
