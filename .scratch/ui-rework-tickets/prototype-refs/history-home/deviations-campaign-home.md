# Don't copy from the campaign-home prototype: #147 Campaign list and home

Scope: `/prototype/campaign-home?variant=B` (tag `prototype-approved/campaign-home` → `a9db8ac`). Spec: [#147](https://github.com/AndreasUnunger/EverythingPath/issues/147). Decisions: [#118 approval, B without next up](https://github.com/AndreasUnunger/EverythingPath/issues/118#issuecomment-5846080538), [#119 states](https://github.com/AndreasUnunger/EverythingPath/issues/119#issuecomment-5846266381), [#121 responsive C](https://github.com/AndreasUnunger/EverythingPath/issues/121#issuecomment-5846528685) and [#122 rollout/query ownership](https://github.com/AndreasUnunger/EverythingPath/issues/122#issuecomment-5846600504).

- **One combined, always-successful header Save.** `EditDetails` waits 400 ms, then calls a single `update(id, { description, inGameDate })` that always sends both fields and cannot fail. Validate first, send only dirty fields through two independent mutations (the new `updateCampaignDescription` and the unchanged `updateCampaignInGameDate`), and track each acknowledgement. On partial failure, report which field saved, keep the failed input and retry only that field. Cancel after a partial save never undoes an accepted write. See #147 §5 "One Save, two independent mutations", §3 ("No prototype's local combined header update authorizes an atomic backend mutation.") and CAMP-12.
- **Create that can't fail and selects instantly.** `CreateFields` uses a hand-rolled `validateName`. The mock then appends the campaign locally after 400 ms and selects its fake `new-<timestamp>` id at once, with no error, unknown-acknowledgement or delayed-list path. Variant B also ignores the state panel's *createReturnsId* toggle. Use react-hook-form/zod and keep values on a definite failure. Select the ID returned by `createCampaign` and wait for the authorized list observation without flashing "unavailable". Never match by name or auto-retry after an ambiguous result. See #147 §1 "Campaign selection and creation" (bullets 3–4), §5 item 1 and the second "One Save" paragraph.
- **An unknown campaign ID silently falls back to the first campaign.** `campaigns.find(c => c.id === selectedId) ?? campaigns[0]`. An explicit ID that is unavailable must never be replaced by the first campaign; use the shell's neutral unavailable state. See #147 §1 (first selection bullet) and §3 approved differences.
- **Selection is mock `place` state.** The address appears only in the state panel, and "open /campaigns/<id> directly" is a button. Real `/campaigns` and `/campaigns/<id>` routes must carry the selection through reload and Back/Forward. See #147 §3 ("URL-backed real selection and authorization replace mock place/data") and CAMP-02.
- **The Recent finished weeks data source and badges.** The mock header comment cites `canonicalHistory.read`, and rows come from a `finished: { week, provenance }[]` array. The badge follows effective provenance, and the rows show no headlines. Call exactly `canonicalHistory.list({ campaignId, limit: 3 })`. Derive **Corrected** from `entryCount > 1` (it takes precedence) and **From setup** from an uncorrected reconstruction. Show up to two headline facts, or **Recorded outcome available**. See #147 §5 "Existing reads and the Finished weeks contract" and §1 (Recent finished weeks bullet). This supersedes #118's `canonicalHistory.read` suggestion (see [#122](https://github.com/AndreasUnunger/EverythingPath/issues/122#issuecomment-5846600504)).
- **Hidden All finished weeks, empty wording and no local retry.** **All finished weeks** renders only when more than three weeks exist, so *Second Table* (two weeks) has none. Zero weeks shows "No finished weeks yet" with no link, and there is no failure state. Always link to `/history`. Show **No finished weeks yet.** with the destination still reachable, and keep preview failures local with **Try again**, so they don't block Continue or Characters. See #147 §1 (Recent finished weeks bullet).
- **Fabricated readiness drives Continue week.** `continuePhase` reads hand-written per-phase `readiness` labels and treats a `locked` Persistent as skipped. Reuse the Week frame's readiness over accepted workspace/draft data and the week's fixed Persistent eligibility, with all-ready → `summary` and warnings alone not blocking. Don't fabricate a target while data loads. See #147 §1 (Continue week bullet), §5 existing reads, WEEK-02 and NAV-15.
- **Mock militia line values.** `officersFilled: 5` is a bare number, "Crossroads Neutral" isn't a rules settlement attitude, and focus falls back to "No focus". Count occupied role categories out of six (not holders). Take rank, focus, teams and attitudes from the current stored militia through shared helpers, with no projected values. See #147 §1 (Militia card bullet) and CAMP-09.
- **Local in-game date formatter and generic list states.** `formatInGameDate` is a mock formatter over `${value}T00:00:00.000Z`. Use the existing fantasy calendar helpers (`src/helpers/ARDateConverter.ts`) and the stored date-only representation. The loading skeleton is one bar plus two blocks, not index/pane-shaped, and the failed card has no **Try again** button. Use layout-shaped skeletons with the **Loading campaigns…** status, and "Campaigns could not be loaded. Please try again." with **Try again**. See #147 §3 ("Existing fantasy calendar conversion replaces mock date formatting"), §1 (Edit bullet) and §1 "States and local editing".
- **Not responsive.** At 390×844 the fixed `w-80` index leaves the pane about 30 px wide (24 px horizontal overflow; see `history-home-campaign-home-phone.png`). The pane scrolls inside its own `overflow-y-auto` section instead of the page. Desktop rows show no description preview. Phone below 768 px is one scrolling list with a single expanded home row, a full-width Continue and the New form in a top row. Desktop from 1280 px has a wider index with description preview lines and a centred max-width page. Pages scroll normally. See #147 §8 (layout bullet) and [#121 C](https://github.com/AndreasUnunger/EverythingPath/issues/121#issuecomment-5846528685).
