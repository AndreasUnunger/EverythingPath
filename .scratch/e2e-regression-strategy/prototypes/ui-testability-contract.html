UI testability contract

Question: can EverythingPath expose stable, player-meaningful observations for browser tests without coupling tests to CSS, component structure, database IDs, or hidden front-end bypasses? Drive the Action Slot lifecycle below and inspect the locator and synchronization contract it implies.

This file proposes a contract; it is not production UI. “Action Slot,” “Action Slot Claim,” “Staged Action Choice,” and “Confirmed Action Choice” follow the project glossary.
Current baseline: production cards and Action Slots are unnamed pointer-driven elements, async states are plain text, and the shared model has no claimant or per-slot claim lifecycle. The initial suite can add semantic identities for current staging and confirmation without waiting for that lifecycle. The contention example below is a future-feature oracle that becomes executable when first-claim locking ships.

Proposed locator inventory

          

            
SurfacePrimary locatorRequired observable contract

            
              
Pages and major panelsgetByRole('main' | 'region', { name })A unique visible heading supplies the accessible name.

              
Forms and controlsgetByRole(..., { name }) or getByLabel(...)Every control has a persistent player-facing label; errors are linked with aria-describedby.

              
Action cardsgetByRole('button', { name: 'Drag Earn Gold' })The drag handle is keyboard focusable and named for the Action Choice. Card styling and DOM nesting are irrelevant.

              
Action SlotsgetByRole('group', { name: 'Activity Slot 1' })The group contains visible lifecycle, claimant, and choice text. Tests scope observations to the group.

              
Async progressgetByRole('status') and disabled initiating controlThe affected region exposes aria-busy; readiness is proven by the resulting domain state, not a timeout.

              
Rejections and failuresgetByRole('alert')Feedback names the rejected operation and leaves the authoritative visible state unchanged.

              
Third-party or semantically opaque surfacegetByTestId(...) as a documented exceptionTest IDs use stable domain language, never CSS names, array positions that can reorder, or Convex/Clerk IDs.

            
          


          
Contract in priority order

          
    
            
  1. Prefer roles and accessible names, then labels, then stable visible state text; use test IDs only where semantics cannot identify the surface reliably.
    2. 
            
  2. Pointer drag tests use a shared Playwright helper that moves between role-located card handles and slots. A player-visible keyboard/tap alternative must call the same production staging path; no hidden browser bypass is allowed.
    3. 
            
  3. Wait on domain outcomes—claimed by Alice, confirmed Earn Gold, character assigned—not sleeps, animation completion, network-idle, or implementation-specific spinners.
    4. 
            
  4. Test-only mutation seams live behind guarded, non-production Convex seed/reset/expire operations. No window.__test, query-string auth bypass, or production-enabled reset endpoint.
    5. 
            
  5. Loading and saving states disable conflicting actions, expose status to assistive technology, and end only when the synchronized domain outcome is visible.
