# Upkeep (#140): don't copy these from `prototype/upkeep` variant A

Pinned at `9c91ed3` (`prototype-approved/upkeep`). Owning spec: [#140](https://github.com/AndreasUnunger/EverythingPath/issues/140). Approval: [#107 resolution](https://github.com/AndreasUnunger/EverythingPath/issues/107#issuecomment-5836751035).

- **Hardcoded rule numbers in `mock.ts`/`variant-a.tsx`/`parts.tsx`.** The prototype hardcodes `minimumGp = rank * 10`, the rank thresholds, Loyalty/Security bonuses, the DCs, the notoriety `>= 100` threshold, and copy such as "the rules cost (minimum treasury at rank 8)" and "short of the 105 that rank 9 needs". Derive every value from the existing pure rule projections instead. See #140 §1 ("No … hardcoded rule arithmetic in components") and §3 ("simplified calculations never ship").
- **Unreasoned recovery adjustments still count.** The recovery cost field writes every keystroke into shared state. `project()` applies the Table Adjustment to the final treasury even while its reason is empty; in the running prototype, cost 60 without a reason already moves Treasury to 25 gp. Keep a changed value without a reason, or an invalid value, local and show field errors. Keep the last valid shared decision and never send a partial adjustment. See #140 §1 "Team conditions" and §5 "Money, recovery and legacy staged removal".
- **Integer-only gp inputs.** `RecoveryCost` accepts only `/^[0-9]+$/`, so the field can't be cleared and rejects decimals. `TransferForm` accepts only whole gp. Parse gp strings exactly to copper precision (0.07 gp = 7 copper), use `react-hook-form`/`zod` with `noValidate`, show styled errors inside the field, and never round stored copper. See #140 §5 "Money, recovery and legacy staged removal".
- **The transfers header includes Table Adjustments.** Section 5's header uses `treasuryAfterGp`, which already includes the recovery Table Adjustment. With a changed recovery cost the prototype shows "Treasury −20 → 25 gp" for a +25 deposit. The header must show the treasury before and after the ordered transfers, including existing effects such as Theft (the prototype has none). Name adjustments under the list without applying them twice. See #140 §1 "Transfers" and the rule that headers show only their own step's contribution.
- **Rank handles only Captain at rank 9.** The prototype checks `r >= 9` and offers Captain cards only, keyed `boon:<personId>`. Keep multiple rank gains, every boon, and open text outcomes (Gift/Skilled/XP). Keep legacy off-list text visible and editable until it is replaced or cleared. Use the existing acknowledgement subjects/IDs, not new keys. See #140 §1 "Rank" and §5.
- **Missing teams ignore queued returns.** A missing team always asks for the return die. Existing queued-return effects must suppress the roll and show the scheduled return instead. A returning team also stays unavailable to this week's Activity. See #140 §1 "Team conditions".
- **Legacy Remove isn't shown.** Having no Remove card is correct, but the prototype also has no surface for an open draft that already stores `remove`. Show that decision and its reason with a clear/repair action and a Militia corrections link. Never drop it silently. See #140 §5 "Money, recovery and legacy staged removal" and the [#107 approval](https://github.com/AndreasUnunger/EverythingPath/issues/107#issuecomment-5836751035) ("Dropping Remove … needs no payload change").
- **First week comes from a scenario toggle.** The skipped state is a panel checkbox while the frame still says "Week 14". Decide the skip from the fixed week-start context, not the displayed week number. See #140 §1 "First militia week".
- **Old frame chrome and no phone layout.** `frame.tsx` has the old top tabs, a fake Summary caption (`requirements + 3` "decisions left") and a fixed 16rem side panel. At 390×844 that panel covers the main column and the page scrolls sideways by 370 px (see `upkeep-upkeep-phone.png`). Take phase framing from responsive-shell variant B and the approved frame (#137): its final Summary caption and phone maintenance positioning. Instant "All changes saved." feedback isn't the save contract either. See #140 §3 and §1 (frame owns save feedback).
- **Mock people, settlements, feats and bonuses are fixtures.** Amara/Doran/Ilse/Pell, Phaendar/Ekkerd/Teilwood, the "Officers (Amara, Ambassador) +2" breakdown and the client-generated `tr-new-N` transfer IDs are fixtures. Read real roster, settlement and modifier facts, and keep stable `transferId`s created through the existing Weekly Draft edit contract. See #140 §3 ("mock people … never ship") and §5 "Approved transfers and rule behavior".
