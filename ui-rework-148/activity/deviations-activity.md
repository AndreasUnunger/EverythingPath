# Activity (#142): don't copy from the prototype

Prototype: `prototype-approved/activity-slots` (`eea4ac7`), `/prototype/activity-slots?variant=E`. Owning spec: [#142](https://github.com/AndreasUnunger/EverythingPath/issues/142). Its only amendment ([#142 comment](https://github.com/AndreasUnunger/EverythingPath/issues/142#issuecomment-5855257402), pointing to [#148 amendment](https://github.com/AndreasUnunger/EverythingPath/issues/148#issuecomment-5855238252)) changes blocking, not behaviour.

- **Hardcoded allowance and client-side remove predicate.** `mock.ts` fixes `rank = 8` and `allowance = 3 + 1`, the header says "3 from rank 8 + 1 Strategist", and the ✕ appears when `index >= allowance && !choice`. Derive the allowance from the rules. Accept `remove_slot` only after a server check against the authoritative allowance and the latest draft. Remove by stable slot ID, and don't reuse `projectActivity().slots[].overAllowance`. See #142 §1 "Header" and §5 "Only new edit: remove_slot".
- **Positional Strategist badge.** `strategist = index === allowance - 1` puts **Strategist +2** on the last slot inside the allowance, even when that slot is empty (Slot 4 in the screenshots). It also says "Adds +2 to organization checks" for Broker Market, which has no check (`162-focus.png`). Show the slot that the existing rules identify, in sequential order. See #142 §1 "Tablet board".
- **Picker has 17 cards, not 23.** Activate Black Market, Activate Refuge, Knowledge Check, Manipulate Events, Restore Character and Special Order are missing. Its `effect`/`check`/`cost` strings are mock text. See #142 §4 ACT-01 and the §5 checklist.
- **Mock eligibility.** `availability()`/`readyTeamsFor()` group cards using static `teamTypes` and a fixed team `status`. "Free / Acts in Action Slot N" comes from `findIndex`, and card colour stripes come from the first matching team's category. Derive grouping and team notes from actor eligibility, prior actions and Upkeep recovery/return timing. Groups are guidance, not filters. See #142 §1 picker and "Team" bullets.
- **Check row.** It uses a single raw "1d20" `Input`, a constant `bonus = 7` and the literal text "Rank and focus +5 · Officers +2", and it sums the total in the component. Drill's training roll is missing. Use Upkeep's shared total control for every roll, including Drill training and Special Order delivery. Take the bonus and breakdown from the pure rules projection, and keep the bonus out of the entered dice total. See #142 §1 "Checks", ACT-13 and WEEK-15/16.
- **Helpful as one atomic toggle.** The `helpful` reducer case flips every slot in one step and reports success at once. The toggle shows on any action with a check (including "By team type"). Move Helpful through ordered existing edits: clear first, then assign. Don't claim success until the edits are accepted, and reconcile on failure. Offer it only on applicable Loyalty/Secrecy/Security checks at a Helpful settlement. See #142 §1 Helpful bullet and §5 "Roll, modifier and reference compatibility".
- **Modifier form.** It is plain `useState` with a −/+ stepper and blocks save only on `value !== 0`. It hardcodes the label "Table modifier" and the mock bonus "Rumor from week 13". Use react-hook-form + zod with signed numeric validation and a required nonblank reason. Use real available bonuses with their usage constraints, and keep unknown/legacy modifiers visible and removable. See #142 §1, §6 and WEEK-14.
- **Dropped fields.** Cost is a static string ("50 gp", "varies") with no entered-cost override. The Rules Exception input shows only while `warnings.length > 0`, and a single `exceptionReason` on the choice is written on every keystroke. Keep calculated vs entered cost (an explicit zero wins). Keep exception reasons in their existing draft collection, with retained old reasons visible and removable. See #142 §1 "Preserve calculated versus entered cost", ACT-11 and ACT-16.
- **Confirmation and remote mocks.** Confirmation only adds `pointer-events-none opacity-50`. Picker cards, the modifier ✕ and the Move-to items still fire, for example by keyboard or in an already-open sheet. The yellow "another player stages Reduce Danger" panel, the `RemoteMark` chip and the header text are simulations. The frame owns save, remote and Confirmation feedback. All mutation controls, including open sheets, must honour Confirmation disabling. See #142 §1 "Frame owns…" and WEEK-06/WEEK-10.
- **Tablet-only layout.** At 390×844 the fixed `w-64` side panel covers the five-column board, and labels clip (`activity-activity-slots-phone.png`). The picker is always `grid-cols-6`. For phone (two-column slot grid, two cards per picker row, Operating from under the allowance) and desktop (≥1280 three-column frame), use `/prototype/responsive-shell?variant=B`. See #142 §3 and §7.
