# Don't copy from the finished-weeks prototype: #146 Finished weeks

Scope: `/prototype/finished-weeks?variant=A` (Ledger, tag `prototype-approved/finished-weeks` → `2e9904c`). This file covers the page, index, audit and record chrome. Deviations in the shared six-section body that come from the summary prototype are listed in [`../summary/deviations-146.md`](../summary/deviations-146.md). Spec: [#146](https://github.com/AndreasUnunger/EverythingPath/issues/146). Decisions: [#117 approval](https://github.com/AndreasUnunger/EverythingPath/issues/117#issuecomment-5845007868), [authoritative amendment](https://github.com/AndreasUnunger/EverythingPath/issues/117#issuecomment-5845032926) and [#119 states](https://github.com/AndreasUnunger/EverythingPath/issues/119#issuecomment-5846266381).

- **An earlier entry shows the effective record's facts.** Selecting Entry 1 of week 12 changes only the header line and chip. All six sections still render the week's single mock body (confirmed: Entry 1 and Entry 3 render identical text). The complete detail must come from the selected immutable record only, never mixing one record's facts with another's. See #146 §1 Page acceptance (Header bullet) and §5 "Frozen-record presentation and compatibility".
- **Unbounded audit list with an inert Earlier entries row.** The disclosure maps every entry (`[...record.entries].reverse()`). **Earlier entries** appears only above five entries and has no handler. Show at most five newest-first entries per page, with real **Earlier entries** paging, reopen-to-newest and a preserved selection. See the [amendment](https://github.com/AndreasUnunger/EverythingPath/issues/117#issuecomment-5845032926) point 4, #146 §1 ("Show **N entries** only…") and §3 ("even where the pinned mock still maps all entries…").
- **Static, complete week index.** All six mock weeks render from one array with no loading window. The real index loads the newest page of `canonicalHistory.list`, prepends older pages through an **Earlier weeks** control, and marks omitted ranges instead of implying missing weeks. The latest row stays at the bottom. See #146 §5 "One shared listing query" (final paragraph) and HIST-08.
- **Selection lives only in React state, and there is no Return to current week.** Clicking rows, arrows or entries never changes the URL (confirmed). The shell's "Week 15" tab is an inert `<span>`. Use `/campaigns/<id>/history?week=<n>` with `recordId`/`beforeSequence` preserved across reload and Back/Forward, and keep a **Return to current week** CTA. See #146 §7 Routes, §4 NAV-12 and NAV-17, and §5 "Scope, selection and states" (selection paragraph).
- **Show all and the entries disclosure stay set across week changes.** Both are component state that isn't keyed by week (confirmed: Show all stays on after ‹, and the disclosure stays open after › ‹). Changing week must reset the audit page/disclosure and Show all. See #146 §1 (Previous/next bullet).
- **Hardcoded headlines, dates and in-progress week.** Row headlines are literal strings. Week 14's row says "Treasury −55 gp" (the Rules Baseline), but the recorded Final treasury went 440 → 585 gp after the adjustment. Dates come from `new Date(iso)` string templates with no `<time>` element, and "Week 15 is in progress" is the `currentWeek` constant. Headlines come from the effective record's before/final `headlineFacts`, with **Recorded outcome available** when empty. Dates come from `createdAt` rendered in `<time dateTime>`, and the in-progress line uses the actual open week. See #146 §5 (headlineFacts bullet and "Date-only extension") and §1 (Tablet landscape bullet).
- **Phase chips that disagree with their items and double-count.** `phaseDelta` is hand-written per week. Week 12's Activity chip says "Training +14" over items that total +8. Its Persistent chip says "Treasury −80 gp" above "No carried events". Its Upkeep chip "Rank 7 → 8" repeats Table Adjustment 1, even though the Rules Baseline rank stays 7. Chips must show recorded net changes that exclude Table Adjustments, and nothing may be double-counted. See #146 §1 (Detail bullet) and §5 ("Phase totals exclude subsequent Table Adjustments").
- **Old page-state copy and shapes.** The state panel shows a text-only "Loading history…", "History could not be loaded. Check campaign access and try again." with **Reload history**, an empty state with no action, and a page-level "Campaign history is unavailable." Use the list/pane skeleton with a **Loading history…** status, "Finished weeks could not be loaded." with **Try again**, "No finished weeks yet." with **Open week N** (or **Set up militia**), and the shell-owned unavailable state. List- and audit-only failures keep the selected detail readable. See #146 §5 "Scope, selection and states" (last paragraph), HIST-07, STATE-05 and the [#119 state table](https://github.com/AndreasUnunger/EverythingPath/issues/119#issuecomment-5846266381).
- **Colour-only Final, whole-gp strings and a fixed three-column Show all grid.** Final differences are only `font-semibold text-sky-300`. Treasury is printed as "585 gp" from mock integers, and the recorded-context block is a fixed `grid-cols-3`. State the difference in text, format treasury copper-exact, and stack the Result and context with labels on narrow screens. See #146 §1 (Result bullet) and §8 (accessibility and responsive bullets).
- **Not responsive.** At 390×844 the fixed `w-56` index squeezes the record to zero width (the `h1` measures 0 px wide, with 336 px of horizontal overflow; see `history-home-finished-weeks-phone.png`). Phone below 768 px is one oldest-first scrolling list with only one expanded week containing the audit toggle and all six sections. Desktop from 1280 px has a wider preview index and a centred max-width page. Follow responsive-pages C. See #146 §8 (layout bullet) and §3.
