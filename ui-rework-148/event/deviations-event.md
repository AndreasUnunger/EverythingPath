# Event (#143): don't copy from the prototype

Prototype: `prototype-approved/event` (`f93ea1c`), `/prototype/event?variant=A`. Spec: [#143](https://github.com/AndreasUnunger/EverythingPath/issues/143). Final approval: [#108 comment](https://github.com/AndreasUnunger/EverythingPath/issues/108#issuecomment-5837858373).

- **Synchronous `normalize()` with global `ev-new-N` IDs.** The mock reducer adds missing occurrences locally with a module counter and no save round-trip. The spec needs identities derived from draft, owner or source, parent and ordinal. Preparation must be a saved `event_tree` or owner `detail` edit that shows pending and failure states, converges across devices and retries with bounds, and no child edit may be sent before its occurrence is accepted (#143 §5 "Existing edits, blank occurrences and concurrency").
- **Plain integer `DieField` everywhere.** It uses a digits-only regex, has no dice-total/dice-count form and no field-level required/invalid errors. It only records an out-of-range warning. Consume Upkeep's shared dual-form total fields for every nested roll, keep zero distinct from clear, and use react-hook-form and zod errors (#143 §3 "Required differences", §5 "Chance, shared rolls and rules versions", §6 first paragraph).
- **Hardcoded rules and mock numbers.** The event table text, `rank = 8`, check bonuses ("Rank and focus +6 · Officers +2"), tier-3-only Sabotage teams, `possible` checks and the chance math are all written in `mock.ts`. Render rules text and derive DCs, bonuses, eligibility and outcomes from the live rules engine and event helpers (#143 §1 last paragraph, §3, §5 "Complete event inputs and outcomes").
- **No Overseer support in Event.** The prototype has no toggle and no "Now on … tapping moves it" hint. Implement "Use Overseer support · +N · one event a week" (no holder name or ability), shared with Persistent via ordinary reconciled edits (#143 §5 "Overseer"; [final shared copy](https://github.com/AndreasUnunger/EverythingPath/issues/109#issuecomment-5837957108)).
- **Raid mitigation is one Attempt/Let it happen per event, and the capture roll is hardcoded to `capture:h-wren`.** Render an independent choice, check and raw capture percentile for every person target (#143 §5 table "Raid"; "Optional mitigation … For per-target mitigation render independent choices").
- **Found Fire rewards are `{personId, name, gp}` with integer gp only.** Weight, alchemical/poison flags, copper precision, stable item identities and edit-in-place are missing. Use the full reward shape with the copper-exact gp parser from #156, and keep the reward exception next to its reward (#143 §5 table "Found Fire").
- **Only Invasion requires *What happened*, and random team picks carry no acknowledgement.** Sickness, Missing in Action, Rivalry and similar events pick a "random" team from cards with no random/GM-selection acknowledgement. Take acknowledgement requiredness from the engine for every relevant type (#143 §5 "What happened uses the correct occurrence acknowledgement subject…"; table rows "Missing in Action; Sickness; Turn Around", "Rivalry").
- **A Sabotaged (negated) event still blocks.** Observed on `166-focus.png`: after a successful Sabotage, the negated Sickness still asks "Team that falls sick: choose one" in This phase. Inactive or negated effects must not invent blockers (#143 §4 EVT-14; §5 "Sabotage … success negates the exact occurrence").
- **Requirement lines lack event identity, and the frame chrome is stale.** Observed: This phase shows "Team that falls sick: choose one" with no event number, and duplicate texts collide as React keys ("Encountered two children with the same key", seen with Rivalry/Sickness twice). The *Week outcome* step also always shows a green check, even while "waiting for the steps above". Name the event and target in every requirement, keep keys stable, and never show a final-looking step for incomplete input (#143 §1 item 4, §6 "Focus and names identify event/target/roll"; use the approved frame's final chrome, §3).
- **The prototype frame is tablet-only.** At 390 px it overflows by 370 px, and the rail overlaps the main column (`event-event-phone.png`). Take phone and desktop from responsive-shell variant B (`/prototype/responsive-shell/screen?variant=B&phase=event`; #143 §7 "Tablet landscape … Phone 390×844 … Desktop ≥1280").
