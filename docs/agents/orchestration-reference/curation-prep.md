# Curation prep: test plans and receipt

Reference for step 2 of the [curation lane](../orchestration/runbook.md#curation-lane): the base runbook text of what `scripts/orchestration/cur-prep.sh` does, verbatim. Read it when a prep turns full unexpectedly or a receipt is not reused.

Write `briefs/cur-<n>-msg.txt` (title "Curate <family>, batch <k> (#<n>)", a body, the Co-Authored-By trailer), then run `$S/cur-prep.sh --branch "$BRANCH" --worktree "$WT" <n> "$EP_ORCH/briefs/cur-<n>-msg.txt"` (as a `gate` job; see [Chaining heavy jobs](../orchestration/runbook.md#chaining-heavy-jobs)). **Legacy numbered alternative only:** `$S/cur-prep.sh <n> "$EP_ORCH/briefs/cur-<n>-msg.txt"`. The orchestrator commits and rebases only through this script. It commits, rebases onto the feature head with the data-file merge, and writes the batch's new shared-store files, counted from git after the rebase and grouped by source, into the report's `prep:shared-store-count` marker block, amending the commit (a report without the block gets a printed count and a warning). Then it runs the format check, `catalog:notice-deps` and the light test plan, which it prints:
- every test file the whole reviewed diff adds or changes, integration tests included;
- every test of each batch whose artifacts (report, inventory, fixtures) the diff touches, so older batches' tests run when a re-bind changes their files;
- the guards: `cross-batch-bindings`, `notice-holds`, `pinned-sources`, the ownership checks' self-tests (`batch-ownership.test.ts`) and their sweep over every applicable inventory (`batch-ownership-sweep.test.ts`), and #757's `review-receipts.test.ts`.

Anything else in the diff makes the prep full: shared tooling, schema or validators (the guards themselves, and any test file that exports helpers, count as validators), fixtures of no batch, an edited shared-store file, a removed test, or a missing guard. Full means the whole of `tests/catalog` plus those tests, as `--full` always does. The landing gate still runs the full suite. The whole Vitest output goes to `$EP_ORCH/logs/cur-<n>-prep-<stamp>-vitest.log`, whose path prep prints; the console gets only the summary. On success prep writes its receipt, `$EP_ORCH/logs/cur-<n>-prep.receipt`: commit, tree, base, lockfile, prep scripts, the test environment (`CI`, `VITEST_MAX_WORKERS` and the other settings that change how tests run) and check configuration, all taken before the checks start. If HEAD, its tree, the feature head or the worktree changes while they run, it writes none and exits 5. The landing queue reuses the receipt instead of preparing again while all of those are unchanged and the worktree is clean; a full prep's receipt covers a light plan but never another test environment. Any rebase, amend or edit after the prep invalidates it. **Done:** it exits 0, the batch is the top commit of its recorded worker branch and the receipt path is printed.
