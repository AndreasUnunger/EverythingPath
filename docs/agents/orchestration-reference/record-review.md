# Record review (drafted to checked)

Reference for [runbook §7](../orchestration/runbook.md#7-fix-round), reached when a review will promote records. The base runbook text, verbatim, then the legacy record step it introduces. `spawn.sh` is retired (2026-11-06), so no new legacy run can start; the step records an existing finished run only.

**Record the review (drafted to checked).** A variant decision, held source or structure record (the `checked` states that authorize a collapse, a supersession or a settlement) is written `drafted`, by implementers and fix rounds alike, even when a review is about to confirm it. Only the orchestrator record step marks one checked. T3 promotion reviews use the capture-owned v2 dispatch and original-message association in [T3 review evidence](../orchestration/t3-reviews.md), starting before dispatch. Bootstrap authentic qualification remains parent-owned; keep real records drafted until it passes. Imported task responses alone cannot bind a review. Ordinary T3 code reviews remain available. The following is the retained legacy `spawn.sh reviewer` procedure (an agent report without run evidence cannot give a receipt):

1. The review brief named each record to confirm and asked for a verdict on each one.
2. Write the IDs the report confirms, one per line, to `$EP_ORCH/briefs/<n>-receipt-ids.txt`; `node --import tsx scripts/catalog-record-review.ts --list` in WT prints every record's status, receipt and ID. Leave out any the review didn't confirm; they stay drafted.
3. In WT: `node --import tsx scripts/catalog-record-review.ts --run $EP_ORCH/runs/<run id> --ids $EP_ORCH/briefs/<n>-receipt-ids.txt`. It refuses a run that isn't a finished reviewer run with a report, a record that isn't drafted, and a record the review didn't see as it is now (the run's `reviewed-records.json` and `reviewed_commit`, saved when the review started). It checks the ledger's consistency only once the records are checked, so drafted merges and same-KEY splits can be promoted, and writes nothing if that fails. It adds the receipt (run id, report SHA-256, each record's ID, source hashes and payload hash) to `scripts/catalog/review-receipts.json`, commits a byte-identical copy of the run's `report.snapshot.md` as `scripts/catalog/review-reports/<run id>.md`, and marks the records checked under it; it never reads the run's `report.md`, which can change later.
4. Commit as `wip: #<n> review receipt`, and run `pnpm test tests/catalog/review-receipts.test.ts`.

A later change to a record's source hashes or payload (a structure record's values or settled items, a decision's identities or mechanics) fails that test: review the record again and record the new run. Before landing, `node --import tsx scripts/catalog-record-review.ts --verify` checks each receipt's committed report copy, and its run's report snapshot from its durable evidence directory; it fails when a copy is missing or differs. `--verify` fails when a run's directory, meta (with its `reviewed_commit`) or report snapshot is missing, unreadable or changed; only the pinned pre-snapshot P6 run (`legacyReviewRuns` in `scripts/catalog/review-receipts.ts`) is checked by its committed report copy alone. Never add to that list.

**Trust boundary.** Run directories are ordinary writable files. The receipt check catches unreviewed or accidental `checked` claims, not a determined forger who edits run directories or the receipts file. Only the orchestrator runs `--run`; workers never do, and never edit `review-receipts.json`, `review-reports/` or a run directory. **Done:** every checked record has a receipt, and the test passes.
