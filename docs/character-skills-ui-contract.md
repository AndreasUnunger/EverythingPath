# #302 Skills UI contract

Use the existing `useCharacterSheet` controller and its single read subscription. Do not query a second sheet or calculate ranks/bonuses in JSX. Hook module: `src/components/character-sheet/use-character-sheet-skills.ts`.

## Exact interfaces

`useCharacterSheetSkills(controller)` takes `Pick<ReturnType<typeof useCharacterSheet>, 'sheet' | 'saveClassLevel'>` and returns:

- `skills`: calculated skills, each `{key:SkillTarget,name:string,ability:Ability,ranks:number,classSkill:boolean,armorCheckPenalty:number}`. Read each statistic from `controller.sheet.calculated.breakdowns[skill.key]`, which contains total/applied/suppressed/conditional, and pass it to the existing StatBreakdown and situation marker conventions.
- `budgets`: null during loading, otherwise `{kind:'ordinary',intelligenceModifier:number,generalFeats:number,racialSkillRanks:number,skillRanks:number|null,skillRankCap:number}`. These are ordinary Hit Dice/rank budgets; companion budgets will follow their own progression rules. User copy: “Ranks use permanent Intelligence at every level.”
- `levels`: stable row `_id`, className/isUnspecified/state, with `metadata` (possibly undefined) from calculated classLevels. Metadata exposes `skillRankBudget:number|null`, `skillRanksSpent:number`, `skillRanksRemaining:number|null`, `skillRankCap:number`, `cumulativeSkillRanks` and `exceededSkillRankCaps`. `ranksFor(key:SkillTarget):number` reads the level's allocation and supports old aliases; `warnings:SheetWarningView[]` contains this row's skillRanks warnings. Use `state.position` for level labels and input names.
- `saveRank(entryId:Id<'characterSheetEntry'>,skill:string,ranks:number):Promise<null>` updates ONE skill atomically; another player's allocation to a different skill is preserved. Same field latest writer wins. No whole-map write from a rank cell.

`useSkillRankForm({ranks:number,save:(ranks:number)=>Promise<unknown>})` returns `form` (react-hook-form values `{value:string}`), `status:SaveStatus`, `save():Promise<'saved'|'failed'>`, `hasRemoteChange:boolean`, `dismissRemoteChange()`. Put a FormProvider around each editor if using FormField. Register/control `value`. Subscribe to formState.isDirty/errors via normal RHF presentation. Save on blur or Enter; retry button calls save. Required/invalid messages are “Ranks are required” and “Ranks must be a whole number of 0 or more”. Structurally valid over-cap/budget ranks MUST save. Failed writes retain draft. Remote changes replace pristine values, preserve dirty values and raise notice. SaveStatus states are idle/saving/saved/error, error contains message.

`useProficiencyChoiceForm({choice:string|null|undefined,save:(choice:string|null)=>Promise<unknown>})` returns the same editor contract, with `{value:string}`. Text is trimmed; blank saves null. It records a weapon choice, with no computed proficiency benefit yet. Use `controller.saveClassLevel(row._id,{proficiencyChoice:choice})`. Label “Proficiency choice at level N”. Empty helper: “Choose a weapon if this class grants a proficiency choice.” Do not add a missing-choice rules warning or invented grant.

Mount each rank editor with a React key containing its stable Class Level row ID and skill key, and each proficiency editor with its stable row ID. Rank inputs carry their name as `aria-label` (no `<label>` element): thirty-five labelled cells would otherwise slow every labelled-control query over the sheet, in tests and assistive tech alike. Each skill's table row carries `data-skill="<key>"` so tests scope to it. Changing the selected level must mount that level's own editor; a dirty draft from the previous level must never travel into the next level. Reordering a row preserves its editor identity and draft. Add a behavioral test that changes selected level with an unsaved rank draft and confirms the next save targets only the selected row's own value.

Class Level favored-class HP/skill/alternative and ability controls already exist in `class-level-choices.tsx` using `useClassLevelChoicesForm` and `saveClassLevel`; preserve them. The alternative note is text only and requires nonempty description; ability choice is available at every row, and an off-milestone selection warns while saving. Extend `class-level-row.tsx` to mount proficiency editor with its own save/error/remote feedback beside the row. The proficiency editor (`class-level-proficiency.tsx`) sits under the row's choices, labelled “Proficiency” with the rest of its name for screen readers, saves when left or on Enter, and shows “Save proficiency” while a draft is unsaved. The row's `ChoicesFeedback` no longer lists the level's `skillRanks` warnings: they sit beside the allocation summary in the Skills block for the chosen level (below). No dice/roll status: skills/choices are deterministic recorded facts and this ticket has no roll input.

## Required behavioral UI tests

1. Rank allocation exposes labeled inputs for selected level, summary spent/budget/cap, class-skill marker, and a total breakdown explaining ranks, one +3 and armor penalty.
2. Rank blur/Enter calls saveRank with stable row ID and skill key when the field is dirty; pristine Enter writes nothing. Editing a valid over-cap value still saves and shows inline advisory warning. Successful saves clear normalization-only drafts for every echo order while preserving newer substantive or invalid rank drafts.
3. Blank/noninteger rank shows field error, no mutation; rejected mutation retains draft with retry feedback; retry saves.
4. Remote update changes pristine field; dirty field survives and notice appears. Row move carries allocations by stable identity.
5. HP and +1 skill favored benefits stay selectable; alternative description persists verbatim without adding an invented bonus. Ability choice remains editable off milestone with advisory warning.
6. Proficiency choice text saves/clears via saveClassLevel and never asserts an invented grant or requires a choice. Labeled field present at each Class Level.
7. No-level and unknown-budget states retain clear copy; maintenance disables writes; phone overflow remains local to skill panel.

Use role/label queries and direct observable behavior like existing character-sheet \*.test.tsx. Parent runs final typecheck/lint/tests and prototype/browser checks outside the restricted sandbox.
