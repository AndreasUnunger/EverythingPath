# Shared draft persistence

Issue [#79](https://github.com/AndreasUnunger/EverythingPath/issues/79) implements the editing portion of [#38](https://github.com/AndreasUnunger/EverythingPath/issues/38) and the adapter seam in [#53](https://github.com/AndreasUnunger/EverythingPath/issues/53). The live application remains on its existing workflow until the canonical cutover.

`createDraftPersistence` owns a Workspace's pending edits, ordered submission and acknowledgement, recovery, and monotonic accepted observations. It accepts a `DraftTransport`; `createMemoryDraftAuthority` supplies deterministic memory authority and `createConvexDraftTransport` supplies the actual authenticated Convex query, mutation and subscription transport. The client returns `accepted` or `failed` and exposes a pending count immediately. A failed edit refreshes accepted state. Temporary transport failures retry the same operation ID and payload; server rejection is final.

Each request contains a stable draft ID, operation ID, observed base revision and semantic edit. The server loads the base from its own retained initial or accepted revision. It derives changed fields from that base, merges disjoint detail fields, checks hierarchical targets, and commits the draft, indexed target rows and operation receipt in one mutation. Target rows retain exact and subtree revisions, including tombstones after an input is cleared; conflict checks use point lookups of a target and its ancestors instead of scanning descendants. The draft document contains no growing target-history array. A whole slot conflicts with any changed descendant; an event tree and embedded persistent decisions have the same relationship. Whole-choice replacement changes choice identity, including replacement with the same action.

The production transport uses generated Convex API references. Its bounded head query is joined with paginated target deltas to deliver authoritative target revision metadata. The client requests 16 items using native Convex pagination options; the server validates and passes those options unchanged, and the revision envelope retains the native result including split metadata. Every page is pinned to one observed revision and status; the server returns a restart marker before using a stale cursor. The client discards mixed pages, retries at most four times, and publishes a monotonic complete observation. Queued intents keep both their actually observed base revision and their own pending draft, so a newly staged or moved choice can immediately receive details. Before dispatch, the Workspace checks that basis against the latest observed targets, excluding only revisions acknowledged as its own earlier accepted edits. It then merges the intended fields onto the observed source. This permits rapid local same-field edits in order while preserving remote changes and letting the server reject races after observation. Older acknowledgements and subscription values cannot move accepted state backwards.

The canonical Convex endpoints are gated to the explicitly configured, owned `canonicalPersistence` E2E campaign on the isolated preview. Authentication and campaign/militia scope are checked independently of that gate. The synthetic fixture stores its complete authority snapshot in `canonicalMilitiaState`; live production initialization remains a subsequent cutover task. Exact Confirmation is implemented in [the confirmation lifecycle](canonical-weekly-confirmation.md). Open drafts retain base snapshots, while the fixture's close operation removes snapshots and leaves operation receipts for deduplication. Normal canonical initialization also captures the initial draft snapshot. Confirmation retires accepted base snapshots and target child rows in bounded cleanup after closure; closed identity and operation receipts remain sufficient for deduplication. Fixture reset and cleanup delete every owned canonical row.

`tests/persistence/contracts.ts` is shared by the deterministic memory test and the real authenticated Convex E2E project. It checks stale disjoint targets, all-target atomic rejection, replace/clear/move/swap, obsolete details, nested decisions, transport retries, closed identity, local submission order, remote queued conflicts, and observations delivered before acknowledgements. Reference validation follows ordered creation choices, allowing an earlier recruited team to be targeted and subsequently removed while rejecting future or foreign references. Separate Convex integration tests exercise argument validation, stored provenance, authority, child references and cleanup. The required browser matrix includes the persistence project and fails if its result is missing or retried.

The final isolated gate `ie6TZA` passed authentication, all five supported tablet journeys, and all ten shared persistence scenarios on first attempts (seven required Playwright tests). Public adapter checks refused outsider, anonymous, and cross-campaign reads and edits without changing the original observation. Indexed tombstones survived repeated creation/clearing and the transport hydrated more than one 16-row page. Independent QA verified 120 tombstone edits, interrupted pagination, queued stage/details, and draft-created references. The live query also verified native page size, end cursor, read limits, and pagination ID options. The full suite passed 844 tests; the rules catalog reported 368 covered cases, 298 explicit remaining gaps, and zero errors. Typecheck and lint pass.
