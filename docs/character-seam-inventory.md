# Character access and Militia Character Facts inventory (#252)

This is the preparation inventory for [PRD #251](https://github.com/AndreasUnunger/EverythingPath/issues/251), surveyed on 2026-10-02. It records the current flat Character consumers left in place by #252 and the implementation tickets that replace or extend them. It does not activate Character Sheets, private Characters, a new Ruleset Version or a migration. The [legacy compatibility inventory, B6](legacy-compatibility-inventory.md#b6-planned-character-sheet-release-cleanup-240) tracks the eventual storage retirement.

## Current contract and prepared seams

The persisted `character` identity stays in place. `campaignId` and `ownerId` are still required; `level` and the six ability scores remain authoritative flat columns. Existing public Character mutations still accept legacy `officer_npc` and normalize it to `npc`; Setup and Militia Correction roster submissions additionally accept and normalize `other_npc`. Archiving sets `isActive` and leaves roster membership, officer roles and team management intact. Ordinary record edits refresh the current canonical militia snapshot, retaining roster Hit Dice overrides, including zero. Resolution Records keep their frozen copies.

- `convex/lib/characterAccess.ts` exposes `listAccessibleCharacters`, `requireCharacterCampaignAccess`, `requireCharacterAccess` for the existing CRUD checks. `convex/lib/canonicalDraftStorage.ts` exposes `requireOrganizationMembership` for canonical scope and Militia Setup. This preserves two existing access policies: Character CRUD uses `hasAccessToOrg`, including its legacy substring match on the user token identifier (`user.tokenIdentifier.includes(orgId)`), whose retirement belongs to [#260](https://github.com/AndreasUnunger/EverythingPath/issues/260); canonical scope requires persisted user membership. Consolidation does not broaden assignment access or introduce private-owner access. `convex/character.ts` retains the public commands. Deletion now checks access before active state, so an outsider receives the access error without learning whether the Character is archived; authorized callers retain the existing deletion errors.
- `convex/lib/militiaCharacterFacts.ts` exposes `calculateMilitiaCharacterFacts`, consumed by `updateCanonicalCharacter` in `convex/lib/canonicalCharacters.ts`. It projects `characterId`, `level`, `strength`, `dexterity`, `constitution`, `intelligence`, `wisdom`, `charisma` and `isActive` from the existing record. Name and kind remain separate; kind still follows the record into the roster. This is the flat-record adapter, not a sheet resolver or a stored actual-Hit-Dice field.
- Refresh timing is unchanged: once canonical militia state exists, the existing refresh increments its revision even for a notes-only edit. Changed-facts-only invalidation, shared Setup calculation and sheet authority belong to later tickets. Creating a record does not put it on the roster.

The [data model](pf-character-sheet-data-model.md), [ADR 0001](adr/0001-one-character-identity.md) and [ADR 0002](adr/0002-characters-owned-by-users-move-between-campaigns.md) describe the target sheet and lifecycle contracts. The prepared seams above deliberately retain the current flat Character model.

## Catalog legal publication seam (#257)

The local attribution gate reports admitted definitions, individual holds, dependent omissions, retained exceptions and failures without activating catalog content. `src/lib/catalog/retained-use-policy.ts` supplies the pure policy for existing uses; Catalog Release and Character Sheet writers must enforce it with the authoritative prior-use inventory and preserve the last usable definition and notice obligations.

[Catalog Release #310](https://github.com/AndreasUnunger/EverythingPath/issues/310) must persist the gate's `requiredNotices` and the legal builder's returned `permanentNoticeSuperset` with each release, then feed both persisted inputs to `buildLegalPageData` for the public page. Previously shipped notice versions remain present through corrections and rollbacks. Held-only content never adds notice requirements for unrelated admissions. The page route currently passes committed defaults explicitly; #257 adds no release persistence, selection enforcement or publication. The owner-authorized project notice is `Keepnet © 2026 Andreas Ununger`.

## Regression evidence

`src/components/characters-officers/characters-page.test.tsx` extends the existing jsdom ledger suite with a saved-statistics regression: edit name, Notes, kind, level and all six scores; verify the public mutation payload; publish accepted query data; verify refreshed officer effects, retained roles and the roster Hit Dice override; reopen the record and read the saved values. Existing cases cover archived editing, archive failure, untouched concurrent fields and drafts surviving week confirmation. These tests mock Convex at the browser interface and do not prove server authorization or persistence; public Convex integration tests supply that evidence.

The existing browser journey is `e2e/character-ledger.spec.ts`, **“players share character and officer assignment changes”**. It exercises two sessions, creation, record inspection, roster and officer corrections, conflicts and layout checks. It is identified for the orchestrator's browser run and was not run in this sandbox. No UI production code changes are needed for #252.
