# Pinned Foundry catalog preview

The [#740 race repair and drafted reassessment](race-import-740.md) records the
current reference-conversion fix, seed replacement and remaining race holds.

Tickets [#253](https://github.com/AndreasUnunger/EverythingPath/issues/253), [#257](https://github.com/AndreasUnunger/EverythingPath/issues/257) and [#303](https://github.com/AndreasUnunger/EverythingPath/issues/303) provide local deterministic extraction, attribution admission and note-curation coverage reports for inspecting the approved Foundry PF1 release data. The command does not create a Catalog Release or publish definitions for player selection.

```sh
pnpm catalog:preview \
  --system /path/to/foundryvtt-pathfinder1 \
  --content /path/to/pf1-content
```

The system checkout must be clean at `v11.11` (`418761d2e16a6037c0156bb4a241f7cea5a2986d`), and the content checkout at `11.4.0` (`02f4ab0d92e0d64f9eb2d127f42fd809cb23db7d`). Both manifest versions must match the pins and share a major. The command checks the repository roots, commits, tracked/untracked input changes and ignored YAML files. It reads the manifests and recursive YAML records; it never runs Foundry, imports its configuration, fetches data, writes to the checkouts or contacts Convex.

The default `.catalog-preview/` directory is git-ignored. `--out /path/to/output` selects another empty directory or one containing only the preview reports below. An output directory cannot overlap either source checkout. The command writes:

- `catalog.json`: mapped entries and supporting resources, input content hashes, pin verification, remaps and counts.
- `unsupported.json`: entries with unmapped mechanics, unresolved references, custom source evidence and fields awaiting feature curation.
- `comparison.json`: every manifest/on-disk pack and every YAML record, with its extraction disposition and reason.
- `curation.json`: exact-bound missing/stale/applied/unused records, drafted/checked counts and unresolved mechanics. See [the curation operator runbook](curation.md) for `catalog:curate`, gap-only resume and the separate prose pass.
- `admission.json`: individually named admitted candidates, holds, dependent omissions, retained exceptions and failures, with input verification and fingerprints binding the report to its extraction, reviewed inputs and legal resources (OGL, Section 8, Paizo notice, project line and permanent notice superset). Outstanding required notices are reported explicitly.

Each file is deterministic for the same inputs and mapping: no timestamps or absolute checkout paths appear in the artifacts. The source fingerprints cover the manifest and ordered YAML paths/bytes. These are preview input hashes, not the complete future Catalog Release manifest. A later release must also fingerprint mapping, curation, legal evidence and supporting resources under the publication contract.

The numbered release's parsers fingerprint includes `src/lib/character-sheet.ts`: its shared schemas validate and shape imported definitions. Editing it therefore requires a new release number even when the normalized output is unchanged. See [the release runbook](releases.md) for the complete fingerprint categories and compatibility deployment requirements.

For the committed reduced fixtures, explicitly permit an unverified source snapshot:

```sh
pnpm catalog:preview \
  --system tests/fixtures/catalog/pf1 \
  --content tests/fixtures/catalog/pf1-content \
  --allow-unverified-checkouts
```

That flag marks the artifacts `inputVerification.status: "unverified"`; it does not bypass manifest version checks or grant release admission. A successful exit means extraction completed and the admission and curation gates passed. Named holds, including reopened accepted assessments and missing or unreviewed notice requirements, do not fail the gate. Duplicate identity, broken structure/reference, unaccounted inventory, missing note/action/Item Ability records, unresolved required curation mechanics and retained-exception reconciliation failures fail the gate. A final admission invariant also fails any admitted candidate lacking required reviewed notices. Admitted content must have a current accepted assessment and all required reviewed notices. An admission failure still writes all five reports and exits nonzero; an extraction or argument error writes no new reports. Inspect `comparison.coverageComplete` as well: this preview is not the complete release-readiness gate.

## Attribution admission

The default reviewed inputs live in `src/lib/catalog/data/`: content-bound Attribution Assessments, evidence and the Section 15 Registry. No accepted content assessments have been inferred from notice lists. A structurally valid, inventory-accounted candidate without an Attribution Assessment is held and listed individually with the reason `missing Attribution Assessment`, its identity and its missing evidence or notices. Explicit importer holds and unresolved assessments also remain held when their content or mapping changes.

An accepted assessment reopens as an individual hold when its content, identity mapping, evidence or notice bindings change. Missing, blank or revoked evidence, missing or unreviewed required notices, absent notice bindings and unidentified source notices also hold the candidate for review. The hold names the review gap, associated evidence IDs and missing notices; stale assessments never admit content. Unrelated reviewed candidates can still be admitted. Review can restore selection at the same stable identity. Changed linked content reopens its parent's whole-content comparison; otherwise accepted parents whose dependencies are held become reported dependent omissions. Inventory, structure/reference, duplicate metadata and retained-exception integrity failures remain release failures.

`--attribution /path/to/reviewed.json` evaluates an explicit reviewed input bundle for a local rehearsal. Its schema, `reviewedAdmissionSchema` in `src/lib/catalog/admission-schema.ts`, requires `assessments`, `evidence` and `registry`, and optionally `retainedUses` and `retainedExceptions`. Inputs are validated at the loading boundary before the gate runs. The input file cannot be inside the output directory. Synthetic test evidence is not shipping review evidence.

The pure `assessCatalogAdmission({ artifact, assessments, evidence, registry, retainedUses, retainedExceptions })` module in `scripts/catalog/admission.ts` evaluates both extracted entries and supporting resources. Its binding helper records the reviewed content, identity mapping, evidence and notices; it does not perform review or establish legal sufficiency. Reports keep source fields unchanged. Output names and fingerprints distinguish the complete extraction from the admission decision, and repeated identical inputs produce identical reports.

The legal-page builder in `src/lib/catalog/legal-page-data.ts` accepts explicit required notices, the persisted permanent notice superset, the selected registry and legal resources. Requirements come from the gate's admitted and retained content; held-only books do not become requirements for unrelated content. Unreviewed registry text is omitted from newly supplied notices and appears as `Notice review pending` when required. Missing text remains an outstanding notice. The owner-authorized project notice is exactly `Keepnet © 2026 Andreas Ununger`, included in Section 15. The owner-approved Section 8 wording (2026-10-03) designates only reproduced Pathfinder rules, mechanics and rules text identified as Open Game Content by their contributors; no other Keepnet content is Open Game Content.

[Private Catalog Release preparation](releases.md) now persists the gate's `requiredNotices`, the builder's returned `permanentNoticeSuperset`, registry and legal resources with each immutable numbered candidate. It preserves previously shipped notice versions and supplies the legal page through the active-release read. Committed defaults remain until an explicit activation selects a prepared release. #257 provides the input seam and local preview; #310 adds private preparation and inspection, while publication remains separate. A passing preview does not establish publication readiness.

The retained-use policy in `src/lib/catalog/retained-use-policy.ts` states the rule the Catalog Release and Character Sheet writers enforce: existing uses keep their last usable definition, and nothing new selects, copies or grants held content. [#411](https://github.com/AndreasUnunger/EverythingPath/issues/411) enforces it for selections, Catalog Copies, automatic Grants and moves; see [Retire or roll back content](releases.md#retire-or-roll-back-content).

The #257 registry records `reviewStatus` and provenance for unreviewed seed text; `checkedAgainst: "unreviewed"` or `"owner-transcription"` describes a seed's source without establishing reviewed coverage. The preview writes a separate `admission.json` report. Content assessment batches and outstanding notice corrections/reviews remain required before content can be admitted.

## Extraction interface and scope

The Character Sheet uses a small typed table for the thirteen editable creature-type progressions. The production `src/lib/catalog/data/resources.json` contains attribution resources, not creature-type records; the imported progressions currently live in pinned test fixtures and the Node-only importer. Importing the full fixture or parser into the client would add unrelated content or server dependencies. The import parity test checks each seed against its pinned resource. Stable creature-type tags identify choices; editable progression names use display names such as "Magical Beast". Older saved tags are shown as display names and save in that form, while custom names are retained.

The Node-only module at `scripts/catalog/import.ts` exposes:

```ts
importCatalog({ systemPath, contentPath, remaps, curation? });
// Promise<{ catalog, unsupported, comparison, curation }>
draftCatalogCuration({ systemPath, contentPath, remaps, curation?, descriptions? });
// Promise<{ records, situations, added, replaced }>
```

It reads inputs and returns values without writes or deployment effects. Callers supply the reviewed remaps explicitly, using an empty array when none apply. Optional curation data holds strict content-bound records and reviewed shared Situations; absent data means no records. The CLI loads `scripts/catalog/reviewed-remaps.json` and `scripts/catalog/reviewed-curation.json` by default, and owns Git verification and output, reporting Catalog Entries and supporting resources separately. The drafter uses the same inventory, loading and retained identity mapping to add only missing bindings. Keeping this module under `scripts/` prevents filesystem, YAML and HTML-parser dependencies from entering the application or Convex bundles. The runtime-independent JSON artifact is the seam available to future publication work.

The preview DTO is deliberately partial and is not the final `CatalogEntryDetail` database union. `detail.kind` names an extracted family; fields contain supported source mappings, and missing or uncurated facts are not asserted to be complete. Examples include class progression and feature references, spell class-tag levels, item weapon/armor details, spell-effect associations and creature-type seed data. Original extracted and curated `modifiers` use `target`, `bonusType`, and a numeric or validated `{ formula }` `value`. Curated Modifiers may also carry conditions; Notes populate `situationalNotes`, and Item Ability mechanics enrich `detail.kind: itemAbility`. No formula is evaluated during import. Unsupported formulas, targets, types and stage dependencies remain flagged in `unsupported`; curated unsupported formulas are retained for runtime warnings and contribute nothing. Spell definitions contribute no ordinary extracted Modifiers. Handwritten target/skill mappings implement the project model without copying Foundry configuration. See [the concrete curation contract](curation.md).

The inventory in `scripts/catalog/inventory.ts` explicitly identifies every pack at both pins. `admitted` in the extraction catalog and comparison reports means **in scope for preview extraction**. The extraction artifact retains `purpose: "preview"` and `releaseAdmission: "not-evaluated"`; the separate `admission.json` reports the attribution gate. Neither a book citation nor a mapped record constitutes an accepted Attribution Assessment. The preview now evaluates note-overlay coverage; records still need corpus curation, publication and feature-completeness gates before new selection. `scripts/catalog/legal/known-notice-holds.json` is the single source for the importer's five source-matched known notice-hold groups: the Dynamite comics (including source codes `DYN0032-E`, `DYN0046-HC` and `DYN0010-A`), Pathfinder Online: Thornkeep, PFS Scenario #4-12, Horror Realms (`PZO9297`), and Shattered Star #4 (`PZO9064`). Matching does not depend on Dynamite publisher metadata being present. Stable upstream-key holds cover Thark Rifle, Radium Pistol and Radium Rifle, whose pinned descriptions cite Worldscape #2 without structured sources; their `sources` remain empty. Notice and notice-chain holds recorded by content batches are enforced by the gate through `scripts/catalog/legal/held-notices.json`; see [curation.md](curation.md#notice-holds-from-content-batches).

The six companion sources are included: system `companion-features` and content `pf-companions`, `pf-familiars`, `pf-companion-features`, `pf-eidolon-forms`, `pf-eidolon-evolutions`. Their actors, classes, attacks and features become supporting resources, not playable Character definitions. Actor-owned embedded game content remains attached to its resource and never receives a global identity. Creature-type records from `racial-hd` also remain resources.

Explicit exclusions include folders, goods/services, third-party and 3.5 packs, the ARG Race Builder folder subtree, and the two named conditional-modifier helpers. ARG exclusion follows folder ancestry, not `racePoints`: ordinary racial traits can have that field. All 12 generic natural attacks, including Swarm Attack, and Unarmed Strike are included by stable ID.

**Record-level `3.5` tags are held, never excluded** (owner policy, 2026-10-08). Only whole 3.5 packs are excluded. A record in an included pack whose `system.tags` contains `3.5` stays a candidate: its curation batch records a specific hold naming the tag, and its unresolved Attribution Assessment keeps it out of admission. #521 holds Blacklight this way. While the policy was open, #522 kept Greater Shield Speech held and #523 gave Bolt of Glory and Reveal True Shape specific tag holds; those holds stand under it.

General monster actors/templates/template abilities may contain companion or cohort dependencies, so they remain unassigned pending review. Mixed collaboration, maladies, rituals and universal monster rules likewise remain visible as unassigned. The whole `pf-society` pack awaits an admission decision; its content records remain unassigned in the comparison report. Unknown directories, unexpected record types, undeclared packs and missing manifest packs prevent coverage from being complete. The importer never silently classifies a new family as excluded or complete.

Descriptions use a parsed HTML allowlist. Script/style/embedded content and unsafe attributes/URLs are removed; resolvable Foundry UUIDs become `catalog:<stable-key>` links, and unresolved targets become labels with report entries. Selected uncurated game fields and actor embedded items remain inspectable as inert report data; runtime command/script/macro/token/configuration fields are not exported. Custom sources retain their actual title and source evidence without inventing a product code. The `gameContent` warning deliberately includes partially mapped records so a missing feature mapping is not confused with complete rules support.

## Racial Trait Grants

[#719](https://github.com/AndreasUnunger/EverythingPath/issues/719) makes the race import produce the [Racial Trait contract](../character-sheet/racial-traits.md). The planning module is `scripts/catalog/racial-traits.ts`; the reviewed per-trait rules are in `scripts/catalog/racial-trait-rules.ts`.

**Binding.** No Foundry race record references a trait record. The only binding is the pf1-content folder `<Core Races|Other Races>/<Race>`, matched to the race record with exactly that name. A record in its `Standard` subfolder is standard. In a flat race folder, a record is standard unless it has a "Replaced Trait(s)" header. Everything else in the race folder is an alternate. Trait `tags` are not an owner and are not imported.

**Output.**

- A race's `detail.racialTraits` lists the stable keys of its standard traits, sorted by key, including its reviewed ability score trait (see below). Races without a folder of their own name (Gnoll, Lizardfolk, Ogre, and both Lashunta records, whose folder is named `Lashunta`) link no trait record, and the import report gives each one an `unlinkedReason`; since #721 their reviewed ability score trait is their only Racial Trait.
- A racial trait's detail adds `raceKeys` (the races of its folder), `standard`, `replaces` and, for alternates, `unresolvedReplacements`. `replaces` comes from the header's names and `@UUID` links, matched against the same race's standard traits without a trailing `(…)` label. "A and B" counts as two names only when both match. A Subrace Standard record without a header replaces the parent's trait of the same name. When any name is unmatched, the alternate imports with an empty `replaces` and lists every name it gives in `unresolvedReplacements`, so the player resolves it by hand.
- **Relocation.** A race change whose target a standard trait's change also carries belongs to that trait. The race drops it, and the trait keeps its own version. When none of the trait's changes on that target maps to a Modifier while the race's does, the race's mapped version moves onto the trait (Kitsune's ability changes, whose trait versions are `untypedPerm`). When several standard traits carry the target and none of their versions maps, no one trait owns it, so the race keeps its change and reports it as ownerless. Relocation therefore never drops a counted Modifier. Race changes no standard trait carries stay on the race, except the fixed ability changes a reviewed ability score trait carries (see below). A trait change with Foundry's `set` operator is not an additive Modifier and stays unmapped; since #720 the same holds for a race's own change (see [Race facts](#race-facts)).
- **Trait facts.** Skilled's `bonusSkillRanks` change of `@attributes.hd.total` becomes `bonusSkillRanksPerLevel: 1`. A trait's named `weaponProf` entries become `proficiencies` `{ baseType }`, using the spelling of the pinned weapon base type they match without spaces, hyphens and case (Dwarf "Battleaxe" is "Battle Axe"). Names that match no base type (such as "Composite Longbow", whose base type is Longbow) are reported and stay prose. So does the "treat X weapons as martial" clause.
- **Reviewed rules.** `reviewedRacialTraitRules` is a small reviewed mapping keyed by pinned trait identity. Each rule names the exact raw changes it consumes, and a record that no longer has them is reported as `racialTraitRule` and imports without the rule.
  - The three "+2 to One Ability Score" traits (Human, Half-Elf, Half-Orc; CRB pp. 27, 24, 25): an `ability.$choice` Modifier of +2. The record's untargeted `base` change maps to `racial`, like the fixed race ability changes.
  - Bonus Feat (CRB p. 27): `grantsSlots: [{ kind: 'feat', count: 1 }]`.
  - Adaptability (CRB p. 24): a feat slot whose `feats` is the Skill Focus key from the Half-Elf race record's `links.supplements`. The trait's own `supplements` list is empty.
  - Multitalented (CRB p. 24): `favoredClassCount: 2`.
  - Elf Blood and Orc Blood (CRB pp. 24, 25): `countsAsRaces` of the Elf and Human, and Human and Orc, race keys. Every other counts-as rule stays prose.
- **Reviewed ability score traits ([#721](https://github.com/AndreasUnunger/EverythingPath/issues/721)).** `reviewedRaceAbilityTraits` in `racial-trait-rules.ts` is a reviewed rule per pinned race, keyed by the race's pinned identity, for the 72 races whose fixed ability changes no pinned trait record owns. Every other race has either a pinned ability score trait (Human, Half-Elf, Half-Orc, Changeling, Gathlain, Kitsune, Vine Leshy, Primitive Human) or no race ability change.
  - Each rule names the race record's exact ability changes (target, formula and type; all are `racial` plain integers), the race's first cited book and page, its description's heading for the line, and the PCGen `<Race> ~ Ability Scores` comparison (`arg_abilities_race.lst` or `cr_abilities_race.lst` pages, Core Essentials, a Bestiary monster race line, or none). A `note` reports a difference between the record and its published text: the Aasimar's truncated "+2 Charisma", Trox's summed +6 Strength, Skinwalker's prose shapechanged bonus, Green Martian's Dynamite source, and the Lashunta records, whose changes merge the Dimorphism adjustments. The trait carries them as the record has them and is not merged with the unbound Sexual Dimorphism record.
  - The trait is a standard Racial Trait of the race: `Ability Score Modifiers (<Race>)`, `raceKeys` the race, `standard: true`. Its description is the race description's list item or paragraph whose leading bold text is the rule's heading, sanitized like any description; with no such line it would be the trait name, which no pinned race needs. Its Modifiers are the race's own ability changes, mapped as the race maps them, and the race no longer carries them. Its `sources` are the race record's, and the race record's notice holds apply to it.
  - **Identity.** `externalKey` is `local/race-ability-scores/<race stable key>`, such as `local/race-ability-scores/pf1/NgIhxRI0axrf3fcO` for the Elf. The `local/` prefix marks a reviewed local rule identity, as `local/crb-condition/<key>` does, and the extra segment can never match a pinned `<repo>/<_id>` key, a candidate key or a remap key. It follows the race's stable key, so a reviewed race remap keeps it with the race, and it is the same on every re-import. Its `upstreamKey` is the race's pinned key: admission accounts for it through the race's inventory row, and its mapping fingerprint covers both keys. Its `attributionFrom` is the race's stable key: admission classifies it with the race's Attribution Assessment, explicit holds, sources and content binding, so it is admitted exactly when its race is and held for the race's reason. It references the race, so each is omitted when the other is unavailable. No assessment is written for it.
  - A rule whose race changes no longer match (a change is missing or extra, a standard trait record carries them, or one no longer maps) is reported `stale` with its reason. The race then keeps its changes, reports a `raceAbilityTrait` unsupported issue, and links no new trait.
  - **Matching.** An alternate's replaced names also match the trait's name and the race's heading, so "Ability Score Modifiers" (or "Ability Scores" for the Locathah) names it. `reviewedTraitNameAliases`, keyed by pinned trait identity, gives the pinned ability score traits the name alternates use: "Ability Score Modifiers" for the half-elf, half-orc and changeling traits (Kindred-Raised, Orc Atavism, Witchborn), and "Constitution Penalty" and "Speed" for Ability Score Modifiers (Gathlain) and Normal Speed (Gathlain) (Tree-Born's text and its record's instructions). Aliases never displace a record's own name. No name is matched fuzzily.
  - **Mapped replacement.** An alternate replaces an ability score trait, pinned or reviewed, only when its own ability changes map to Modifiers: a raw ability change that maps, a change a reviewed rule maps, or an applicable Curation Overlay Modifier on an `ability.*` target. Otherwise that name stays unmatched, so no base adjustment goes dormant without its replacement. The reason is "ability line is prose only; resolves once curated with structured Modifiers" when it has no ability change, and "its own ability changes do not map to Modifiers; resolves once they are reviewed or curated as Modifiers" when it has unmapped ones. `reviewedRacialTraitRules` maps the alternates' own changes the text gives: Orc Atavism's `base` +2 Strength as racial and its untargeted −2 as an ability choice (ARG p. 212, the record's page, unverified), Kindred-Raised's untargeted +2 as a choice (Inner Sea Races p. 212), Tree-Born's `base` +2 Dexterity (Ultimate Wilderness p. 10) and Keen Kitsune's three `untypedPerm` changes (Blood of the Beast p. 12) as racial. Every one of an alternate's own ability changes must map, not just one. Dual Talent now maps two independently saved choices and resolves all three replacements; duplicates warn and contribute once.
  - `reviewedAbilityLineSubraces` lists the 37 heritage subraces (Aasimar, Tiefling, Dhampir, Skinwalker, and the Ifrit, Oread, Sylph and Undine elemental subraces) whose "Base Statistics" stands for their race's ability score trait. Existing curation structures 28; #740 maps seven remaining exact native lines with description-hash guards. Ragebred and Scaleheart remain source-conflicted: no automatic ability mapping or baseline replacement, with unresolved Base Statistics, baseline contribution and manual control retained. Publisher values, citations and errata remain unverified; this fallback does not complete SP3/#740. Source disagreements and notice holds remain. "Base Statistics" stands for the ability score trait of the one race the folder binds; a folder that bound several would leave it unmatched (no pinned folder does). Oversized Goblins consumes its raw deltas and supplies the complete replacement adjustments and Medium size. The racial subtypes' "Base Statistics" (Arctic Elf and 52 others) stays unmatched with no reason, and their race's ability score trait stays active. So does that of the ten Changeling subraces, whose Subrace Standard ability records replace the changeling trait by name.
  - The Half-Orc ability choice keeps CRB p. 25, which the SYS record and #719 cite; its evidence notes PCGen's SOURCEPAGE p. 24.
- **Reviewed class schedules (S3, [#716](https://github.com/AndreasUnunger/EverythingPath/issues/716)).** A class whose upstream key is a reviewed schedule's `classKey` (`scripts/catalog/pcgen/schedules.ts`, 33 classes) takes its `featuresByLevel` from `scheduleRows`, not from Foundry's `links.classAssociations` (`scripts/catalog/class-schedules.ts`, before curation, so a structure record still overrides it). Every other class keeps Foundry's links byte for byte.
  - Foundry's links are checked against the schedule as `compareSchedule` does. A feature's acquisition at its table level is a row. A reviewed non-row that is no table feature stays at its Foundry level, after the table's rows of that level: Fighter Heavy Armor at 7, Cleric and Druid Bonus Languages at 1. A reviewed non-row that is a table feature takes the table's level: Barbarian Tireless Rage moves from 16 to 17. A row Foundry doesn't link is placed too: Fighter Armor Mastery at 19, Hunter Orisons at 1.
  - Refusals, never drops: an unexplained Foundry link, a scheduled key that doesn't resolve and a remapped scheduled key each add a `links.classAssociations` unsupported item naming the key and level, so admission fails the class as broken structure. A feature that doesn't resolve gives no rows or increments. None of the 33 pinned classes has a refusal.
  - **Increments.** The class also emits `incrementEntries` (315 across the 21 launch classes, 521 across all 33), unchanged except that `upstreamKey` and `attributionFrom` are the parent feature's key. As with #721, admission classifies an increment with its parent's Attribution Assessment, holds and binding, so it is admitted, held or failed with its parent; its `parentFeature` and `attributionFrom` are references, so it is omitted when its parent is unavailable. The class depends on every row, so a class assessment binds every increment body.
  - **Bonus feat slots.** `scripts/catalog/pcgen/schedule-slots.ts` holds four cited rules, each giving the acquisition and every increment one `{ kind: 'feat', count: 1, featTypes }` slot: Fighter bonus feats `Combat` (11 rows), Cavalier bonus feat `Combat` (3), Magus bonus feats `Combat`, `Item Creation`, `Metamagic` (3) and Inquisitor teamwork feat `Teamwork` (6). The Wizard's (metamagic, item creation or Spell Mastery), the monks' named lists, and Ranger combat style and Sorcerer and Bloodrager bloodline feats stay outstanding, with no default slot (#716/#739).
- **Casting ability (S3).** A class's `casting.ability` is the stored ability name (`classCastingSchema`): `details.ts` maps Foundry's code through one table (`str` → `strength` … `cha` → `charisma`). Any other code, even a stored name such as `intelligence`, is kept and reported as a `casting.ability` unsupported item, and admission fails the class (`Unknown casting ability code: <code>.`), so it never reaches the candidate adapter. Every pinned caster's casting (28 classes) equals its reviewed record.
- **Reviewed race outputs.** The Curation Overlay binds #328's race records to the race's raw text, and they keep binding there.
  - A race note's outputs apply to the one standard trait with a note on the same target. When several traits do, the owner is the one trait whose note states all of the race note's numbers (Drow Immunities, not Poison Use (Drow)). While the race's record is checked, it stands in for the owner's own notes on that target that state exactly the race note's numbers: they are not required inputs, the drafter does not draft them, and the report lists them as `coveredTraitNotes`. An owner note that states other numbers stays required and is listed in `uncoveredTraitNotes` (Stonecunning (Dwarf) notes +2 and 10 ft; the race note states only +2). A drafted race record covers nothing. Only a checked note record of the trait for the target supersedes the race's note; the race record is then no longer a required input and is reported stale. A drafted trait record does not supersede it. A race note no trait owns stays on the race.
  - `reviewedDescriptionRehomes` moves a checked race description output onto the trait that carries the same fact as a raw change or note. That change is not mapped again, and that note is not a required input. This covers Gnome Magic's illusion DC (CRB p. 23), Kitsune Magic, Svirfneblin Magic, Shadow Magic (Wayang)'s shadow DC (a note), and the natural armor of Ghoran, Changeling, Grindylow, Cecaelia, Nagaji and Reptoid. A rule whose description, record, or trait change or note has changed is reported `stale`, and its race keeps the output.
  - An output whose owning trait is outside the extraction, as in a bounded preview, is not applied. The race reports it as a `curation.home` unsupported issue.
- `grantsSlots[].feats` holds stable keys. Admission follows `racialTraits`, `replaces` and slot feats as references, so a race's content closure now includes its traits.

**Import report.** `catalog.json` has a `racialTraits` section. Per race it lists the linked and unlinked standard traits, the trait names in the race description with no record (`unmatchedTraitNames`, a name check that also counts race facts such as Type, Size and Base Speed), the relocated changes, the `ownerlessModifiers` and notes left on the race, the re-homed, covered, uncovered and stale notes, whether its `weaponProf` has an owner, and `lostModifiers` and `addedModifiers`. Those two compare the extracted Modifiers of the single-entry race with those of the race and its traits. It also lists `overlaps`, a race and trait Modifier on one statistic, and `latentOverlaps`, a race Modifier on a statistic that a standard trait's uncurated note or unmapped change covers. A `dc.school.*` target counts as `spellDC`, so a reviewed race school DC beside its trait's raw DC is reported. The trait's curation batch must not count a latent overlap again. The report then lists each alternate with an unmatched name or no header, with its reviewed `reason` where it has one, and the state of each description re-home rule. `abilityTraits` lists each applied or stale reviewed ability score trait rule with its evidence, PCGen comparison and note; the summary also counts the unused rules whose race is outside the inputs.

**Observed pinned run (2026-10-08, feature branch at `1f0b4872`).** The full pinned preview links 536 standard traits to 75 of the 80 races, and no standard trait is left unlinked; the other 5 each report an `unlinkedReason`. It relocates 105 race changes and re-homes 43 race notes, with no stale note. Those notes stand in for 40 trait notes; 4 trait notes state other numbers and stay required (Aphorite, Dwarf Stonecunning, and two Orang-Pendak notes). ## Race facts

[#720](https://github.com/AndreasUnunger/EverythingPath/issues/720) maps the race facts #328 left unmapped onto the sheet's existing statistics, and reports the rest with a reason. The mapping lives in `scripts/catalog/map.ts`, `details.ts` and `racial-trait-rules.ts`.

- **Skill keys.** Skill Modifier targets and class skills use the runtime keys, such as `skill.per`, on every kind of entry. Before, the importer spelled them out (`skill.perception`), so no imported skill Modifier counted on a sheet and imported class skills were silently lost. Artistry and Lore (`art`, `lor`) have no sheet skill: their changes and class skills are reported. Every other mapped target was already a runtime target; a test asserts that for every imported Modifier.
- **Natural armor.** A race's or Racial Trait's `nac` change is a natural armor bonus to AC (`ac.natural`, `naturalArmor`), whatever Foundry's type (`base`, `racial` or `untyped`). So it does not stack with another natural armor bonus, such as a fused eidolon's. This maps Gnoll, Lizardfolk and Ogre on the race and Armor (Merfolk) on its trait. It also retypes the eight trait outputs #719 counted as `racial` or `untyped`. The one exception is `reviewedRacialNaturalArmor`: Granite Skin (Oread) gives "a +1 racial bonus to natural armor" (ARG p. 144), so it stays `racial` on `ac.natural`. Bonuses of different types stack (CRB p. 12), so it adds to another natural armor bonus. No other pinned race or trait natural armor text says "racial bonus". The five races whose checked #328 description supplies their natural armor (Ghoran, Changeling, Grindylow, Cecaelia, Nagaji) report their raw race change rather than count it beside that output. Their natural armor trait owns the change, so in the full import this changes nothing.
- **Size.** A race's `system.size` maps to `detail.size`, and a record without one gets Foundry's `med` default. The abbreviations are `fine dim tiny sm med lg huge grg col`. The resolver derives every size modifier from that fact, so the importer emits none. An unknown size is reported, and the race imports without one.
- **Speeds.** The sheet has no movement statistic. Each race speed is reported under `speeds`, one issue per mode, with the bonus it would also give: the climb speed's +8 racial bonus on Climb checks, the swim speed's +8 on Swim checks to perform a special action or avoid a hazard, and the fly speed's maneuverability modifier and Fly class skill. A fly speed always reports its `flyManeuverability`. A record that leaves it empty, as Strix and Syrinx do, reports `average`, which is how Foundry reads it and what both race texts say. A Racial Trait's `landSpeed`, `climbSpeed`, `swimSpeed`, `flySpeed` or `burrowSpeed` change is reported the same way.
- **Spell resistance.** The sheet has no spell resistance statistic, so a race or trait `spellResist` change is reported.
- **`set` changes.** A race's or trait's change with Foundry's `set` operator replaces a value and is never an additive Modifier. Normal Speed (Vanara) encodes its climb speed as `skill.clm set 20`, which therefore never becomes a Climb bonus. For race and trait changes, the unmapped report's `value` includes the `operator`.
- **Reviewed unsupported changes.** `reviewedUnsupportedChanges` lists, by pinned identity, exact raw changes that are reported with a reviewed reason instead of mapping. Ghoran's raw Escape Artist −2 applies only "to escape a grapple against a creature that has a bite attack with the grab ability" (Delicious, Ultimate Wilderness p. 15). No shared Situation fits it exactly, and its checked description record already states it as a Situational Note, so it never counts unconditionally. Primitive Feat's `bonusFeats` change has no reviewed bonus feat rule, because its only source is a Paizo blog post.
- **Proficiencies.** A race's own `weaponProf` list that no standard trait carries (the Drow Noble's) becomes race `proficiencies` with the trait matcher's `{ baseType }`. A creature type's category keys (Outsider's `simple` and `martial`) become `{ category }` grants. Other strings stay prose and are reported. A race mapped without a Racial Trait plan, which has no pf1-content pack to own or resolve its weapon familiarity, reports each named weapon. No race or trait record has `armorProf`.
- **Racial Hit Dice** stay 0 on every imported race.
- **Description corrections.** A race's stated values in its description, such as a base weight, are corrected only by a [reviewed description correction](curation.md#reviewed-description-corrections) under an owner decision; the race's description bindings keep the raw text.

## Reviewed identity remaps

Keys are `<repo>/<_id>` (`pf1` or `pf1-content`), with pack and name stored independently. Archetypes and prestige classes imported from PCGen and the PRD (#716) use `everythingpath/<id>` keys with a lowercase hyphenated id, such as `everythingpath/ranger-beast-master` (`catalogKeySchema`, `src/lib/catalog/imported-entry-schema.ts`); remaps, Curation Overlay bindings and curation batch selections accept both forms. Upstream redirect tables are never loaded. The committed `scripts/catalog/reviewed-remaps.json` is initially empty because this first extraction has no previously published identities.

Each future record requires `from`, `to`, `kind`, `reason`, `evidence`, `reviewedBy`, and ISO `reviewedOn`. Two orientations are supported:

- A current upstream `from` to an absent historical `to` retains the historical output identity after a move or recreated ID.
- An absent historical `from` to a current `to` records an alias after a reviewed merge; several historical aliases may resolve to that one definition.

Entries, description links and mapped references resolve through the same identity map, including links that already contain a retained identity. Kind mismatches, duplicate origins, cycles/chains and attempts to combine two present definitions fail. Resolving competing live definitions requires explicit curation before supplying a remap. Unused remaps are reported as `applied: false`.

## PCGen sources (#716)

- **Locators and provenance.** A PCGen record is located by `{file, line, key}`; KEY is stable and the line is only reported. A record belongs to one identity. A decision cites each source once with the effective source hash it reviewed (`sourceSha256`, the hash structure records bind), and only a checked review, which names its reviewer, its date and its review receipt (below), applies; a decision whose bound hashes no longer match is stale and authorizes no collapse or supersession (`isCurrentDecision`), whichever record changed. `locatorRemaps` record a reviewed file or KEY rename: `from` is a locator the identity holds, `to` one no other identity holds, and each locator is remapped at most once, so no remap is ambiguous or chained. - **Pin.** `prdPin` (`scripts/catalog/inventory.ts`) records the manifest's sha256 and a `contentSha256` over the manifest and every listed file, hashed the way the Foundry pins are (`loadCatalogInputs`, `import.ts`). `verifyPrdCapture` (`scripts/catalog/prd-pin.ts`) fails on a changed manifest, a missing file or a changed one. - **Supplement.** The owner's 2026-10-31 decision adds one page beside the capture, not in it: the Advanced Race Guide's age, height and weight page (`advancedRaceGuide/ageHeightWeight.html`), which the core race pages link and whose random starting ages name class groups.
