# Weekly Draft Workspace and Upkeep

Issue [#81](https://github.com/AndreasUnunger/EverythingPath/issues/81) introduces the feature seam specified by [#34](https://github.com/AndreasUnunger/EverythingPath/issues/34). `useWeeklyDraftWorkspace` returns `unavailable`, `loading`, `failed`, or `ready`. Only `ready` exposes its discriminated Phase View and the semantic `edit`, `viewPhase`, and `confirm` families. It exposes domain choices, values, requirements and affordances without the synchronized draft, revision, query assembly, flushing, DOM references, or field setters.

The private Workspace store owns phase selection, optimistic projection, accepted-preview matching, save feedback, recovery, and successor observation. Each player chooses a phase independently, including while an edit is pending. A failed edit removes its forecast and restores the latest accepted values using the standard failed-save feedback. Persistent Phase availability comes from fixed week-start eligibility. A relevant source change refreshes the accepted preview; whole-week Confirmation delegates the exact-review barrier to persistence. The source subscription discovers the new empty draft after Confirmation.

The browser boundary uses the application's authenticated Convex client. `/canonical-workspace?campaign=…` is reachable only as an isolated feature surface: its backend source and write queries require the configured owned preview campaign and independent campaign membership. Unsupported campaigns receive unavailable state. The existing live board and its behavior remain unchanged; this is not a cutover or a dual write.

Upkeep presents calculated rank, training, treasury, minimum funds, check bonuses, modifier explanations and required dice. It supports missing-team return rolls, disabled-team decisions, nearest-settlement choice, staged copper transfers, rank-boon acknowledgements and reasoned Rules Exceptions. Its focused semantic roll, settlement, team and transfer edits preserve other inputs and use the same server-derived conflict checks as the existing whole-Upkeep operation. Upkeep settlement, team, officer and transfer-direction choices use selectable cards with tap/keyboard activation and pointer placement into a highlighted selection area. Invalid or cancelled drops return the card with visible feedback and preserve the prior choice. Pointer capture, geometry and click suppression stay in a browser-only adapter, outside the Workspace. Recovery costs prefill the rules baseline; a changed amount requires a reason and atomically stages a typed treasury adjustment with the team decision. The adjustment applies after the entire weekly baseline, and choosing leave or remove clears it. Summary displays both differing treasury outcomes. Advisory warnings name the affected choice and explain the departure. Activity action cards are the subsequent #82 increment; the other phase shells currently expose their readiness facts.

Browser forms use React Hook Form, Zod and the existing shadcn controls. Whole-number entry accepts ASCII digits or blank, retains the previous value on invalid input, preserves zero, and emits an explicit clear. Dice remain raw; calculated totals are displayed separately. Multi-die rolls are entered in order, and clearing an earlier die explicitly clears the remaining dice in that roll. Required, format and range feedback have different meanings: missing input remains a partial draft, malformed text is rejected, and out-of-range numeric dice remain entered with an advisory warning. A browser `beforeunload` handler warns only while semantic edits or Confirmation are pending; it does not block local phase navigation.

Workspace tests observe hook states, Phase Views and semantic outcomes through the public seam. They verify loading/unavailable/failure recovery, deterministic Upkeep facts, independent navigation, latest-value restoration after a real in-memory conflict, and fixed persistent eligibility. Input tests cover invalid entry, zero, clear and styled field errors. Backend integration covers the gated source, member authority and successor discovery. The shared adapter suite now includes focused Upkeep stale/disjoint operations and zero/clear, exercised in memory and the actual preview.

The required browser matrix includes a separate two-player canonical Workspace journey in addition to the supported legacy journeys and persistence contracts. QA holds a real mutation WebSocket frame while preserving query traffic, checks visible pending state, changes phase, dismisses a real page-exit warning, accepts another player's competing edit, then releases the original stale request and checks recovery. It also checks keyboard/paste entry, transfers, Summary readiness, ordinary-player Confirmation, both players reaching the successor, and tablet/phone/desktop screenshots. Missing or retried Workspace results fail the gate.
